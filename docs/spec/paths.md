# 寻路与路线

实现见 `packages/sim/src/paths.js`（寻路）和 `packages/sim/src/routes.js`（路线）。格 (行, 列) 的中心在坐标 (x = 列, y = 行)，行 0 在最下。

### 寻路-1 流场

敌人总是走最短路径。每个目标格有一张流场：

- **搜索**：从目标格出发做 SPFA（先进先出队列），每走一格代价 1；地面单位走出地穴格的一步代价 1,000,000（地图-4），走出类障碍物地块（建成的液压式高台，守御-5）的一步代价 1,000。
- **邻接**：四个邻格，依次是上（行 + 1）、右、下、左。
- **松弛**：只有更短的距离才更新一个格，所以每个格保留最先到达它的那个父格。
- **可通行**：地面单位只能走「全部可通行」（ALL）的格；空中单位能走除「不可通行」（NONE）以外的格。
- **格边**：两格之间的格边对这类单位封闭时（地图-2），不能在这两格之间走。
- 走不到目标的格没有距离。

- 来源：[PRTS「作战机制」oldid=433935](https://prts.wiki/index.php?title=%E4%BD%9C%E6%88%98%E6%9C%BA%E5%88%B6&oldid=433935)「行动的基本原理」：「所有敌人始终选择最短路径行动」，寻路算法为 SPFA，地面单位不进入地面不可通行地块；数据：level.mapData.tiles[].passableMask；邻接顺序和松弛规则为推断 INF-0028；类障碍物地块的代价为推断 INF-0205

### 寻路-2 平滑

搜索之后，按格的编号（逐行，从行 0 开始）依次处理每个格：它的指向从父格开始，只要指向的下一格还在视线内，就沿指向往前移。指向是就地修改的，所以处理一个格时，前面的格已经平滑过了。

- **视线**：从这个格到那个格的 Bresenham 直线上每一格都可通行，地面单位的还不能有地穴格（地图-4）。斜着走一步时，旁边的两个格也都要可通行。直线的每一步都不能跨过封闭的格边；斜着走一步时，交于那个角的四条格边都不能封闭（地图-2）。
- **不允许斜走的路线**（allowDiagonalMove 为 false）：只认同一行或同一列的视线。
- 敌人从所在格出发，沿平滑后的指向一格格前进，每一段走直线。
- **经过的格子**：从一格到目标格的路线经过的格子，是沿平滑后的指向的各段 Bresenham 直线上的格子（两端都算）；内容按它查询敌人会走过哪些格。

- 来源：推断 INF-0028；数据：level.routes[].allowDiagonalMove

### 寻路-3 所在格

一个位置所在的格按四舍六入五成双取整（体积-1）；在地图外的位置没有所在格。

- 来源：[PRTS「作战机制」oldid=433935](https://prts.wiki/index.php?title=%E4%BD%9C%E6%88%98%E6%9C%BA%E5%88%B6&oldid=433935)：「受击方坐标经round函数取整(四舍六入五成双)」；寻路也用同一取整为推断 INF-0028

### 路线-1 路线指令

路线由检查点依次组成，最后加一段走到终点：

| 检查点 | 做什么 |
|---|---|
| `MOVE` | 走到这一格，终点是格中心加上检查点的偏移（reachOffset，x 加到列、y 加到行） |
| `PATROL_MOVE` | 同 MOVE，但是巡逻点（路线-3） |
| `WAIT_FOR_SECONDS` | 原地停 n 秒（换算成帧，时间-2） |
| `WAIT_CURRENT_FRAGMENT_TIME` | 停到这个敌人所在的出怪片段开始后第 n 秒（片段开始的帧加 n 秒的帧数） |
| `DISAPPEAR` | 进入消失状态（路线-4）；时间大于 0 时接着停这么久 |
| `APPEAR_AT_POS` | 离开消失状态，立刻移到这一格的中心 |

- **其他类型**：数据里出现其他类型的检查点时，拒绝这条路线。
- **等待的计时**：
  - 停 n 秒就是停 n 个整帧。
  - 这一帧里是走着到达等待点的，从下一帧开始计。
  - 停 0 秒不停。
- **一帧内连续执行**：消失、出现不占时间。到达一个点后，这一帧剩下的移动量继续用在下一段移动上；遇到等待时作废。

- 来源：[PRTS「作战机制」oldid=433935](https://prts.wiki/index.php?title=%E4%BD%9C%E6%88%98%E6%9C%BA%E5%88%B6&oldid=433935)：MOVE「移动到指定位置后执行下一步」，WAIT_FOR_SECONDS「等待一定时间后执行下一步」，WAIT_CURRENT_FRAGMENT_TIME「当前兵团开始后时间达到一定值后执行下一步」，APPEAR_AT_POS「离开消失状态，瞬移到指定位置后执行下一步」，偏移量「不为0即可使敌人不走直线」；数据：level.routes[].checkpoints；帧的计法和偏移的坐标轴为推断 INF-0029

### 路线-2 走一段路

- **计划路线**：开始一段移动时，按流场（寻路-1、寻路-2）从所在格计划路线，经过的点存进单位的状态，之后沿这些点走直线。
  - 空中路线直接直线走向终点。
  - 单位自己的行动方式变成飞行后，当前这段路也直线走向终点，不等路线本身是空中路线；路径距离按这段空中路线算。变成飞行的这一帧，它还要走，就从这里重新计划（敌能-34）。变回地面后（行动方式记为 `WALK`，敌能-48），当前这段路再按地面流场计划，这一帧还要走就从这里重新计划；只有现在是飞行的单位才变回地面，地面单位的计划不动。为推断 INF-0384。
  - 流场到不了终点时，直线走向终点。
  - 敌人站在格中心以外，并且从当前位置到第一个点的直线会穿过它不能走的格时，先回到所在格的中心。直线穿过的格：格 (r, c) 占 [c − ½, c + ½] × [r − ½, r + ½]；正好沿两格的边界走时算在行号或列号较大的那一格；正好经过角点时斜着跨过，不算旁边的两格。直线跨过封闭的格边（地图-2）时也算穿过不能走的格。
- **速度**：每帧前进 移动速度 × moveMultiplier ÷ 30 格（移动-1）。

- 来源：[PRTS「行动方式」oldid=429783](https://prts.wiki/index.php?title=%E8%A1%8C%E5%8A%A8%E6%96%B9%E5%BC%8F&oldid=429783)：地面单位绕开不可通行的格，飞行单位一般不绕路；计划一次后沿点走、回到格中心的规则为推断 INF-0028；单位自己变成飞行后当前路段直线走向终点、路径距离按这段空中路线算、变成的这一帧就重新计划为推断 INF-0306；从飞行回到地面后按地面流场重新计划为推断 INF-0384

### 路线-3 巡逻

连续的几个巡逻点组成一个闭环：走到最后一个后，回到第一个，一直循环，不会走到终点。

- 来源：[PRTS「作战机制」oldid=433935](https://prts.wiki/index.php?title=%E4%BD%9C%E6%88%98%E6%9C%BA%E5%88%B6&oldid=433935)：巡逻点「经过后不会从路径点序列中消失的路径点，会被敌人单位重复经过」，「存在巡逻路径点时，敌人单位将始终留在战场上沿闭合路径移动，除非其因某些特殊能力退场」；闭环由连续的巡逻点组成为推断 INF-0029

### 路线-4 消失

消失状态的敌人：

- 不能被选中（索敌-2），不能被阻挡（阻挡-1），已被阻挡的会被放开；
- 不受伤害（伤害-7），也不攻击（敌人攻击-1）；
- 照常执行路线上的等待和出现。

- 来源：[PRTS「作战机制」oldid=433935](https://prts.wiki/index.php?title=%E4%BD%9C%E6%88%98%E6%9C%BA%E5%88%B6&oldid=433935)：DISAPPEAR「进入消失状态(无敌且透明，发生任意移动后取消)并等待一定时间后执行下一步」，消失时无法被阻挡、选中；「消失不是隐匿，故该目标依旧会受到锁定其的攻击而受伤」（已锁定的投射物在 M3c 处理）

### 路线-5 被内容移动

内容可以把单位直接放到某个位置（`displace`）。敌人从新位置重新规划它正在走的移动段（寻路-1、寻路-2）；它所在的路线段、正在进行的等待都不变。阻挡照常按位置判定（阻挡-3）。内容在敌人自己的回合里用 `place` 放到 (x, y) 时同样如此，并且这一帧不再沿路线走，放置就是这一帧的移动。直接 `displace` 不跳过这一帧的路线。

- 来源：设计决定（kit 搬运、拖拽单位等效果由内容实现，引擎只提供放置；位移的官方规则——力度、重量——尚未实现）

### 路线-6 绕行

内容可以让正在走移动段的敌人绕行到某格：它先走到这格的中心，再走到这一段原来的终点，两段都按 路线-2 计划，存进它的路线点；它所在的路线段不变。不在移动段上时不绕行。之后重新计划这一段（路线-5）时，绕行就不再保留。

- 来源：[PRTS「“复仇者”」oldid=435337](https://prts.wiki/index.php?title=%E2%80%9C%E5%A4%8D%E4%BB%87%E8%80%85%E2%80%9D&oldid=435337)「将其所在地块中心设置为自身下一检查点」；之后再走向原来的终点为推断 INF-0155
