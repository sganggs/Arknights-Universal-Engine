# 数据 mod

数据 mod 是装在主机上的一组数据文件：改官方的干员、关卡、敌人和召唤物的数值，或者新增干员和关卡。官方内容本身是内置的 mod `official`，其他 mod 按顺序叠在它上面。设计见 [ADR 0037](../adr/0037-data-mods-first.md)、[ADR 0064](../adr/0064-data-mod-loader-and-sdk.md)。

### mod-1 清单

- 一个 mod 是一个文件夹：清单 `pack.json` 加它列出的文件。文件夹名就是 mod 的 id：小写字母、数字、`_`、`-`，1–32 个字符，不能是 `official`。
- 清单的字段沿用 Stronghold Protocol 的 `pack.json`（编辑器用的 `$schema` 可以写，加载时不看）：`type`（`data`）、`version`（语义化版本）、`app`（适用的引擎版本范围，mod-2）、`name`（1–64 个字符）、`englishName`、`authors`（至多 16 个名字）、`credits`、`license`、`files`；新增 `dependencies`（mod id → 版本范围）和 `priority`（−1000 到 1000 的整数，默认 0）。
- `files.data` 是一个或多个数据文件的路径（至多 64 个）：文件夹里的相对路径，用 `/` 分隔，不含 `..`，以 `.json` 结尾，至多 128 个字符；同一个文件（不分大小写）不能列两次。
- 「问题」让 mod 不加载：类型不对或是还没支持的 `assets`，版本、名字、文件列表、依赖、优先级写错，`app` 不是版本范围。「警告」不影响加载：清单写的 `id` 与文件夹名不同（以文件夹为准）、没写 `app` 或本引擎版本不在其内、可选的文字字段写错（当作没写）、不认识的字段或文件角色。
- 读清单不会抛出异常。

- 来源：设计决定，见 [ADR 0064](../adr/0064-data-mod-loader-and-sdk.md)；字段与问题、警告之分取自 Stronghold Protocol 的 `docs/PACKS.md` §2（GPL-3.0-or-later）

### mod-2 版本与版本范围

- 版本是语义化版本 `主.次.修订`，可带预发布和构建后缀；比较时预发布版本当作它的正式版（0.2.0-dev 算 0.2.0）。
- 版本范围：`||` 分隔几个备选，满足其一即可；每个备选是用空格连接的几个条件，都要满足。条件有：`>=`、`>`、`<=`、`<`、`=` 加完整版本，不带符号的完整版本（等于），`^1.2.3`（主版本不变；主版本为 0 时次版本不变，次版本也为 0 时修订号不变），`~1.2.3`（次版本不变），`1.x`、`1.2.x`（`*` 同 `x`），`*`。
- 引擎的版本是 0.1.4。

- 来源：设计决定，见 [ADR 0064](../adr/0064-data-mod-loader-and-sdk.md)；语法取自 Stronghold Protocol 的 `docs/PACKS.md` §2 与 [语义化版本 2.0.0](https://semver.org/lang/zh-CN/)

### mod-3 加载顺序

- 一个 mod 在它依赖的 mod 之后加载。几个 mod 同时可以加载时，`priority` 小的先加载，相同时按 id 的字典序。后加载的 mod 覆盖先加载的。
- 依赖没装、版本不在范围内、或者没能加载时，这个 mod 不加载，依赖它的 mod 也不加载。依赖绕成圈的 mod 都不加载。两个 mod 的 id 相同时，后一个不加载。
- 每个 mod 要么整个加载，要么完全不加载；每个 mod 都有一份报告：是否加载、问题、警告。

- 来源：设计决定，见 [ADR 0064](../adr/0064-data-mod-loader-and-sdk.md)

### mod-4 数据文件、表与 id

- 数据文件是一个对象，键是表名，值是「内容 id → 补丁或新记录」；编辑器用的 `$schema` 可以写，加载时不看。表有：`operators`（干员，可改可加）、`levels`（关卡，可改可加）、`enemies`（敌人，只能改，改的是所有关卡里这个敌人）、`tokens`（召唤物，只能改）。
- 内容 id 由字母、数字、`_`、`-` 组成，至多 64 个字符，前面可以有一个「mod id 加 `:`」。已有的 id（官方的，或先加载的 mod 加的）按补丁处理（mod-5）；不存在的 id 必须以本 mod 的 id 加 `:` 开头，按新记录原样加入；其他情况是问题。
- 一个 mod 的数据文件按清单的顺序处理；每个文件里按表的顺序 `operators`、`levels`、`enemies`、`tokens` 处理，所以同一个文件里新加的关卡，敌人补丁也会改到。
- 新加的干员也出现在可选干员的名单里，带上加它的 mod 和它的外观（mod-11）。

- 来源：设计决定，见 [ADR 0064](../adr/0064-data-mod-loader-and-sdk.md)、[ADR 0037](../adr/0037-data-mods-first.md)（前缀）

### mod-5 补丁

- 补丁按 JSON Merge Patch（RFC 7386）合并：补丁里的对象按键合并，值为 `null` 的键被删除，数组和其他值整体替换。补丁不改动原来的记录，得到一份新的。
- 目标是数组、补丁是对象时，按元素寻址：
  - 键全是十进制数字：按下标，下标超出数组是问题；
  - 否则按元素的名字：每个元素（`null` 除外）都有文字的 `key` 时按 `key`，都有文字的 `id` 时按 `id`；空数组按它的名字（`blackboard` 按 `key`，`skills`、`modules` 按 `id`）。没有名字可用、或名字有重复时是问题。
  - 元素的值为 `null` 时删除这个元素；名字不存在时在末尾新增一个元素，名字字段写在最前面，新元素必须写成对象。
- 元素都是 `{ key, value }` 的数组（blackboard）里，可以直接写值：`{ "atk_scale": 6 }` 等于 `{ "atk_scale": { "value": 6 } }`。
- 合并补丁不能把值设成 `null`（`null` 表示删除）。

- 来源：设计决定，见 [ADR 0064](../adr/0064-data-mod-loader-and-sdk.md)；[RFC 7386](https://www.rfc-editor.org/rfc/rfc7386)

### mod-6 记录的结构检查

- mod 改过或加入的每条记录都要通过和官方数据同样的结构检查：每个字段的类型和取值范围，哪些字段必须有、哪些可以没有，不能有不认识的字段。官方的全部干员、召唤物、关卡和敌人都通过这些检查。
- 关卡还检查：地块铺满宽和高；出怪动作的路线存在，出的敌人是这一关的；预部署单位在地图内。记录里的 `level.id` 与关卡的 id 相同。
- 干员还检查：分支是官方的分支之一；召唤物是官方的召唤物；官方干员不写 `look`，新干员必须写（mod-11）。
- 一条记录至多报 20 个问题。

- 来源：设计决定，见 [ADR 0064](../adr/0064-data-mod-loader-and-sdk.md)；字段和范围取自生成的官方数据 `packages/content/data/`（全部记录通过检查：`packages/content/test/mods.test.js`）

### mod-7 冲突警告

- 两个 mod 改了同一个值（同一个路径，或一个路径包含另一个），而且后加载的不直接或间接依赖先加载的，给出一条警告：两个 mod、记录、至多三个路径，以及后加载的为准。依赖关系里的覆盖不算冲突，同一个 mod 自己的改动也不算。
- 路径按补丁的写法记录（按名字或按下标）。

- 来源：设计决定，见 [ADR 0064](../adr/0064-data-mod-loader-and-sdk.md)、[ADR 0037](../adr/0037-data-mods-first.md)（按依赖和优先级给出冲突警告）

### mod-8 内容来源与对局内容

- 内容来源给出：可选干员的名单、关卡、按 id 取干员和召唤物的记录、加载了的 mod（id、版本、数据的 sha256）、每个 mod 的报告和冲突警告。官方内容是没有 mod 的来源。
- 对局内容（同步-9）从内容来源做出；用了 mod 时，内容带上加载了的 mod 的 id、版本和 sha256，进入内容哈希（同步-10）。一个 mod 数据的 sha256 按清单顺序把每个数据文件的「路径、换行、内容、换行」连在一起计算。
- 黄金结果、一致性检查和兼容检查只用官方内容。

- 来源：设计决定，见 [ADR 0064](../adr/0064-data-mod-loader-and-sdk.md)、[ADR 0037](../adr/0037-data-mods-first.md)

### mod-9 严格解析与上限

- 数据文件只用 JSON 解析；键名 `__proto__`、`constructor`、`prototype` 是问题；嵌套至多 64 层。数据 mod 不带脚本。
- 单个数据文件至多 8 MiB，一个 mod 的数据文件合计至多 32 MiB（按 UTF-8 字节），至多 64 个 mod。

- 来源：设计决定，见 [ADR 0064](../adr/0064-data-mod-loader-and-sdk.md)、[ADR 0039](../adr/0039-mod-assets.md)（大小上限、严格解析、不带脚本）

### mod-10 主机的列表与客户端的核对

- 主机开服时加载一次 mod，不热更新。它提供一份列表（第 1 版）：引擎版本，加载了的 mod 按加载顺序，每个带 id、版本、数据的 sha256、清单，以及每个数据文件的路径、字节数和 sha256。
- 客户端按列表从主机取每个文件（`<mod id>/<路径>`），核对字节数和 sha256，不符时不进入对局；再用同样的方法做出内容来源。
- sha256 用纯 JavaScript 计算：局域网里用 HTTP 打开的页面没有 `crypto.subtle`。
- 列表来自网络，客户端先检查它的结构：字段、id、路径、字节数上限、sha256 的写法。

- 来源：设计决定，见 [ADR 0064](../adr/0064-data-mod-loader-and-sdk.md)、[ADR 0039](../adr/0039-mod-assets.md)（哈希清单由主机提供，客户端逐个核对）；SHA-256 见 [FIPS 180-4](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.180-4.pdf)

### mod-11 新干员的外观

- 新干员用 `look` 写一名官方干员的 id，画面和声音用那名干员的：战斗模型、头像和立绘、语音。
- 名单里新干员的条目带 `mod`（加它的 mod）和 `look`。

- 来源：设计决定，见 [ADR 0064](../adr/0064-data-mod-loader-and-sdk.md)（mod 自带素材以后再做，[ADR 0039](../adr/0039-mod-assets.md)）

### mod-12 aue 命令行

`@aue/sdk` 的 `aue` 命令给 mod 作者用：

- `aue mod new <id>`：从模板建一个 mod：适用本引擎版本的 `pack.json`、一个数据文件（把陈的二技能 10 级的攻击倍率从 500% 改成 600%）、说明。模板原样就能通过检查。id 不对或文件夹已存在时报错。
- `aue mod check <文件夹>…`：像主机那样把这些 mod 一起叠到官方内容上（mod-3），列出每个 mod 加载了没有、问题、警告、加了和改了哪些记录，以及冲突。读文件夹时只读清单列出的数据文件；文件必须在文件夹里（解析链接后）、不超过上限、是 UTF-8 文本，开头的字节顺序标记去掉。有 mod 没加载时退出码为 1。一个不含 `pack.json` 的文件夹代表它下面所有含 `pack.json` 的子文件夹。
- `aue mod test <文件夹>…`：用 mod 后的内容跑无画面的对局：mod 加了或改了的每名干员，以最高练度（最后一个精英阶段的满级、最后一个技能的最高等级、无模组）在 mod 加了或改了的第一个关卡上（没有就是 IG-1 逃离火线）作战；mod 加了或改了的每个关卡，两种难度各跑一次，不部署干员。脚本每 15 帧部署能部署的第一张卡，放在离某条路线终点最近的可部署格，朝向那条路线的起点；手动技能一就绪就开。每局跑到结束或给定的秒数（默认 180 秒）；出错的对局报告错误，不中断其他对局。
- `aue mod pack <文件夹>`：打成 zip：一个以 mod id 命名的文件夹，里面是 `pack.json`、数据文件，有的话再加上 `README.md`、`LICENSE`、`LICENSE.md`、`LICENSE.txt`、`NOTICE.md`，以及列出这些文件 sha256 的 `SHA256SUMS`。每次打出的字节相同（时间戳固定为 1980-01-01）。清单或数据文件读不通时拒绝打包。

- 来源：设计决定，见 [ADR 0064](../adr/0064-data-mod-loader-and-sdk.md)、[ADR 0055](../adr/0055-sdk-prepared-now-built-after-mvp.md)（`aue` 命令行：创建、检查、测试、打包 mod）

### mod-13 JSON Schema

- `pack.json` 和数据文件各有一份 JSON Schema（草案 2020-12），放在 `packages/sdk/schemas/`，文件里写 `$schema` 指向仓库主分支上的这两份文件，编辑器就能补全和检查。
- 数据文件的 JSON Schema 由记录的结构检查（mod-6）和补丁规则（mod-5）生成：每个字段都可以不写，可选字段可以写 `null`；数组可以整体写，也可以写成按下标、`key` 或 `id` 寻址的对象；完整的新记录也符合。重复出现的较大的子结构放进 `$defs` 引用。
- 仓库里的两份文件必须与生成的相同。

- 来源：设计决定，见 [ADR 0064](../adr/0064-data-mod-loader-and-sdk.md)；[JSON Schema 2020-12](https://json-schema.org/draft/2020-12)
