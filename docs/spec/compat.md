# Stronghold 兼容层

兼容层只在 `packages/content/src/compat/` 里（ADR 0045）。kit 的源码不改，只由导入路径映射表把它们的导入指向我们的模块（ADR 0010）。

### 兼容-1 网格尺寸

Stronghold 的常量模块把网格的列数 `COLS`、行数 `ROWS` 给成固定的数；我们的地图大小每关不同。

- 映射表把 kit 对常量模块的导入指向兼容层，其中 `COLS`、`ROWS` 是活的绑定：运行一场战斗的内容代码时（`withGrid`），它们是这一关的宽和高；之后恢复成之前的值，内容代码抛出异常或两场战斗的代码嵌套时也一样。
- kit 在函数里读 `COLS`、`ROWS`（编码、解码格子键，边界检查，遍历网格），每次调用读到的是当时这一关的尺寸。
- 在模块加载时就读的，值固定在加载那一刻。所以兼容层加载 kit 时，`COLS`、`ROWS` 都是 64（`LOAD_GRID`），大于任何关卡（数据里最大 50 × 44）：按地图大小生成的「整行」「整图」列表覆盖每一关，地图外的格子在算攻击范围时去掉（索敌-1）。固定提交的 Stronghold 内容代码里只有一处这样取值：`kits/ops/chess_char_4_20-fartth.js` 第 11 行的 `LINE`（远牙三技能的无限直线范围）。

- 来源：设计决定，见 [ADR 0010](../adr/0010-import-mapping-table.md)（只改写导入路径，不改 kit 源码）、[ADR 0012](../adr/0012-stronghold-compatible-core.md)、[ADR 0045](../adr/0045-unit-field-ownership-compat-isolation.md)；用法统计：ArknightsGameData 的 3943 个关卡中地图最宽 50、最高 44；固定的 Stronghold 提交中 83 个文件引用 `COLS` / `ROWS`（内容代码 66 个），按语法树分析，内容代码在加载时读取的只有上面一处（`packages/content/test/compat-grid.test.js`，ADR 0056）

### 兼容-2 映射表与 kit 的载入

- **映射表**：Stronghold 的 kit 所及的每个引擎模块（按它在 Stronghold 仓库里的路径）对应兼容层里的一个替身模块：`server/sim/` 下的 constants、detmath、dir、targeting、body、damage、attack、buffs、ai、professions、simdata，以及 `server/data.js`、`shared/constants.js`、`shared/potential.js`，和 `shared/plugins/` 下的 steps、textNumber、limits、officialBounds、rules、dataUtils，共 20 个。attack 与 dataUtils 是 Stronghold v0.3.2 起 kit 才用到的：v0.3.2 把伤害结算整理成 `server/sim/attack.js` 一个入口，kit 从这里取原先在 damage 里的名字。dataUtils 的原文件没有引擎依赖，但 `jsonProblems` 的复杂度超出源码限制，映射到只导出 `RECORD_MAPS`（插件记录的 id 前缀与 id 字段，按数据表）的替身，值与原文件相同——kit 的载入闭包只用到它。steps、textNumber、limits 是 Stronghold v0.3.1 的原文件（没有引擎依赖，原样载入，放在同一目录并互相引用）。kit 以外的战斗内容（兼容-7）另及 4 个，共 24 个：`shared/i18n.js`（消息与数据名，照搬为纯数据）以及只有准备阶段用到的 `server/sim/rng.js`、`shared/garrisonUpgrades.js`、`shared/plugins/skillSpec.js`（同一个替身，名字都是缺口）。officialBounds 的原文件超出源码限制（`visit`、`appendFactionBounds` 的复杂度，`boundMessage`、`exceed` 的参数个数），映射到冷缓存替身：没有装入官方数据快照，读数与原文件在缓存为空时相同——没有官方最大值，计数上限是下限 64，步长不把亚帧间隔抬到一帧。rules 的原文件没有引擎依赖，但 `grantedBondsByMorph` 的复杂度超出源码限制，映射到只导出这个函数的替身，判定与原函数相同：官方模式下少于两件不给盟约，必须有一件能给出盟约的装备，其余装备的 `giveBondId` 在 `bondOk` 通过时给出，plus 模式一件即可且只给最左一件。内容文件（`server/sim/content/` 下：kit、它们共用的帮手、召唤物与道具模块）原样载入，只把它们对引擎模块的导入换成替身。映射表里没有的引擎模块被导入时报错，kit 新增的依赖立刻显出来。
- **加载钩子**：Node 的加载钩子由映射表生成，给出 Stronghold 仓库的根和兼容层的目录，就按表改写 Stronghold 文件里的相对导入。
- **替身**：
  - 纯函数直接给出：方向（按名字的四个朝向，朝右写的偏移每步转四分之一：右 (dr, dc)、上 (dc, −dr)、左 (−dr, −dc)、下 (−dc, dr)；第 0 行在最下，上为行号增大，与 方向-1 一致；不出现 −0）用 Stronghold 的写法移植；确定性数学用引擎自己的（与它逐位一致，数值-2…数值-5）；常量中 `COLS`、`ROWS` 按 兼容-1，`TICK` 为一帧（时间-1），其余先取 Stronghold v0.2.4 的值，用到它们的 kit 与对照比较时逐个核对。增益的合计（buffs 的 `aggregateMods`：同名修饰加算 × 层数，`…Mul` 连乘至层数次方，闪避按独立概率合并）与攻击档案（ai 的 `effectiveProfile`，兼容-4）也用 Stronghold 的写法移植。持续效果的伤害说明（damage 的 `periodicDamage`）为记在来源名下的无来源真实伤害（伤害-7），不可闪避，带 `dot`、`periodic` 标签。单位是否在元素爆发中（`burstLocked`，元素-3）读单位的 `burstLock` 标记（兼容-4）。attack 另给出：伤害的施加方式（`damageApplyWay`：自带的，否则投射物为远程、攻击为近战、其余为无）、攻击类型（`damageAttackType`：自带的，否则溅射、带 `dot`/`necrosis`/`apoptosis` 标签的为持续、其余为普通）、闪避方式（`damageDodgeMode`：不判定闪避、判定但不能取消、普通）、按原因取消一次伤害（`cancelDamage`：伤害声明不接受的原因不取消，落空照样记下）和给转移预留一份生命伤害（`reserveTransfer`，见 兼容-4），都用 Stronghold 的写法移植。记录在某一潜能下的样子（potential 的 `atPotential`）就是记录本身：我们的记录本来就按所选潜能造出（兼容-3），没有 Stronghold 记录里的潜能注记。
  - 还没有提供的名字以「缺口」存在：kit 载入时它在，被调用时报错并写明模块和名字，不会悄悄做别的事。
- 固定版本的对照（Stronghold v0.3.1）里 72 个干员 kit（`kits/ops/op-*.js`）都原样载入；129 个棋子 kit（`kits/ops/chess_*.js`，卫戍协议的棋子，Stronghold Protocol 的 aue 分支用）也都能载入。v0.3.2 以后的 kit 也能载入，但还不是固定版本（兼容-6），见来源。

- 来源：设计决定，见 [ADR 0010](../adr/0010-import-mapping-table.md)、[ADR 0012](../adr/0012-stronghold-compatible-core.md)；方向的写法取自 Stronghold 的 `server/sim/dir.js`（GPL-3.0-or-later）；插件模块取自 Stronghold v0.3.1 的 `shared/plugins/`（GPL-3.0-or-later），officialBounds 为冷缓存替身、rules 为 `grantedBondsByMorph` 替身，见上；v0.2.4 的导入闭包按语法统计是 72 个 kit、9 个共用内容文件、引擎模块 13 个、61 个名字，棋子 kit 另用到 6 个名字（常量 `CHAIN_RADIUS`、`ELEMENT_GAUGE_MAX`，取固定提交的值；`powi` 用引擎自己的；`attackCountdown`、`applyRedirectCut`、`redirectShare` 先作缺口）；钉到 v0.3.1 后映射表为 18 个（kit 载入闭包另及 `shared/plugins/rules.js`）；Stronghold v0.3.2 起 kit 另导入 `server/sim/attack.js`（v0.4.0 中 186 个 kit 文件，10 个名字）与 `shared/plugins/dataUtils.js`（`RECORD_MAPS`，经 `content/index.js`、`support/index.js`），映射表为 20 个；加上之后，v0.3.3 的 72 个干员 kit 与 129 个棋子 kit、v0.4.0（`b6d8b2ef`）的 75 个干员 kit、129 个棋子 kit 与 57 个版本 kit（`kits/ops/ver-*.js`）都能载入（2026-11-15 测得；未加时 v0.3.2 与 v0.3.3 都只能载入 0 个干员 kit、18 个棋子 kit）；attack 的写法取自 Stronghold v0.4.0 的 `server/sim/attack/helpers.js`、`transfer.js`（GPL-3.0-or-later）；其中 `attackCountdown` 与 吟游者的 `bardRegen`、`targeting.aggroCmp` 已在 2026-11-16 补上（兼容-4）

### 兼容-3 kit 的输入：记录与定义

kit 的工厂收到 `(bb, chess, def)`：所选技能的 blackboard、这名干员的记录、规范化后的定义。兼容层用引擎自己的练度数据（干员-1…干员-7）造出它们，形状同 Stronghold 的「自选」记录，但练度任意：

- **身份**：干员 id；所在的「槽位」写作 `aue_<干员 id>`。宿主给了这个棋子的事实时（兼容-7），记录的 `chessId`、`baseId` 取事实里的棋子 id，`isGolden` 取事实里的是否精锐；没有事实时没有 `isGolden`。
- **属性**：这一练度下干员自己的属性（精英化与等级、信赖、潜能、模组的加值），不含天赋的效果——天赋由 kit 自己施加。部署费用、阻挡数、攻击间隔、再部署时间等照搬；技力回复为每秒 1。
- **范围**：这一精英阶段的攻击范围；**特性**：已解锁的最后一个特性 blackboard，模组改写特性时用模组的值覆盖（干员-7）；模组只作展示的特性部件（`DISPLAY`，追加一行说明）带的 blackboard 也并入，同 Stronghold 的记录（这一行的效果游戏里由隐藏天赋给出，kit 从特性读它）。
- **天赋**：每个天赋已解锁的最后一项；模组改写天赋时，模组的值覆盖、天赋原有的其余键保留，改写不属于任何天赋的（序号 −1，如攻击范围）另加一条。
- **技能**：这一精英阶段已解锁的每个技能在所选技能等级上的数据；所选的那个作为 `skill`。
- **技能范围**：kit 技能说明的 `targeting.rangeGrid`（朝右写的 [行, 列] 偏移）是技能运行时的攻击范围（技能-8），按这时的内容读——kit 在开始时原地重算也照用（司霆惊蛰 S2 的低地洪水填充）；没有时用记录的范围。
- **说明文字**：技能、天赋、模组的天赋改动和召唤物的说明同 Stronghold 的记录：占位符（`{key}`、`{-key}`、`{key:0%}`）按 blackboard 代入，`desc` 去掉官方的富文本标记，`descRaw` 保留标记（kit 会从说明里读数，如望的「最多拥有8（+1）枚」）。
- **模组**：所选模组及等级；没有时为未装备。另列出这一练度下已解锁的每个模组，各在所选模组等级上：平加的属性、特性（不改写特性时为空）、天赋改动——都按模组自己写的值（一个天赋部分里已解锁的最后一项，即潜能对应的那一档），不与天赋合并。
- **不带模组的记录**：属性、特性、天赋各再给一份不带模组的（`statsBase`、`traitBase`、`talentsBase`）。kit 用它们分开天赋本身与模组的追加：推进之王的「万兽之王」在模组「糖果盒」3 级下，给全体先锋的取天赋本身的 +10%，自身额外的 +8% 取模组的改动（合并后的天赋里两者同名，只剩 8%）。
- **定义**：记录按 Stronghold 的规则规范化，再带上所选技能、模组与潜能。
- **召唤物原始记录**：战斗对象的 `data.rawToken(id)` 给出召唤物在其召唤者练度下的记录（这局里第一个持有它的棋子的），场上上限另放在顶层，同 Stronghold 的 tokens.json；没有棋子持有它时为空。

- 来源：设计决定，见 [ADR 0016](../adr/0016-arbitrary-operator-levels.md)（任意练度在数据层计算）；记录的形状与规范化、天赋的合并规则取自 Stronghold 的 `server/sim/simdata.js`、`shared/loadoutRecord.js`（GPL-3.0-or-later）；模组选项的字段（`modules[]`、`…Base`）同 Stronghold 的数据说明 `docs/DATA.md` §2.2；72 个 kit 在每个技能（精英二满级、最后一个模组 3 级）与精英零、精英一 1 级下都能由这些输入造出 kit


### 兼容-4 战斗里的 kit

kit 在战斗里看到的是 Stronghold 的战斗对象；兼容层用引擎的世界给出它（`packages/content/src/compat/battle.js`、`unit.js`、`skill.js`、`kits.js`）：

- **挂接**：内容的开局挂接（钩子-4）造出这局的战斗对象；牌组里每个有 kit 的干员得到一个「棋子」（同一干员的几份各一个，同步-9），整局一个，同 Stronghold 的棋盘棋子。棋子的 id 也整局不变：开局前从引擎预留（钩子-4 的 `reserveIds`，按座位、牌组顺序），部署前、两次部署之间都一样；按 id 找单位时它找得到棋子，其他单位用引擎的 id。开局前每个棋子的 kit 装一次：kit 自己的安装和各天赋的安装。
- **部署**：干员每次入场时（钩子-3 的 `enter`：它的特性、天赋、被动技能生效之前，同 Stronghold 先装好 kit 再启动被动技能），先于任何 kit 对这次部署的处理，把它的棋子绑定到引擎的单位上，再把它的持久增益重新给上。撤退或阵亡后棋子解绑，kit 装下的钩子与计时器留着，看得到之后的每次部署。
- **单位**：kit 看到的单位有 Stronghold 的字段与读取方式：位置、格子、朝向、生命、当前属性、阻挡的敌人、增益，都从引擎的状态现读。属性的标记另以 Stronghold 的名字给出（`invulnerable`、`bind`、`noHeal`、反隐 `reveal`），元素爆发中另有 `burstLock`。kit 自己存的状态（`mem`、`trait`）在兼容层，不在引擎的状态里（ADR 0057）；`trait` 里 Stronghold 的职业安装存的、引擎也有同样状态的几项，读写的是引擎的状态（见下「职业的状态」）。没有 kit 的干员和敌人也以同样的样子给出。kit 选友方时（光环、治疗、给增益）不选孤立的单位，自己除外。另有：部署时刻（`deployedAt`，战斗秒数）、在地面（`ground`：我方在地面格、敌方不在空中）、是不是领袖（`isBoss`）、距下次攻击的秒数（`atkCd`）、上次损失生命的时刻（`lastHitAt`：战斗秒数，没有损失过为负无穷，每次部署的单位各有各的；取引擎扣了生命之后的 `damaged` 事件，量大于 0 的才算，推断 INF-1102）、基础攻击范围（`baseRangeKeys`：自己的攻击范围——kit 写过的，否则记录里的——在所在格与朝向的格子，按范围表里的次序，不含技能的范围、额外格和攻击距离扩展；不在场的棋子和敌人没有，推断 INF-1100）；攻击档案（`effectiveProfile`）为它特性的档案，技能运行且说明有攻击或索敌覆盖时叠上这些覆盖（兼容-5）。战斗对象给出战斗秒数 `time`（这一帧开始时，帧 × 1/30，同一帧的处理里都相同）和是否已经结束（`finished`，结束-1）。朝向的一步（`fwd`，方向-1：向上为行 + 1）；额外攻击格（`extraRangeKeys`，战斗对象的 `setExtraRange` 设置，攻击-1）。
- **职业的状态**（`unit.trait`）：Stronghold 的职业安装把状态存在 `unit.trait` 里，自己实现特性的 kit 读写它们。兼容层的 `trait` 是一个普通对象，kit 可以往里加自己的项；下面几项在干员在场时读写引擎自己的状态，写入立刻生效，没有第二份：`ramp`（解放者的蓄力，攻击力的加成比例）是引擎蓄力 Buff（职业-12）的攻击加成，写入落到最近的一级，不超过全部级数；`funnelTarget`、`funnelScale`（驭械术师的浮游单元）是引擎浮游 Buff 记的上次目标和它现在的倍率（没有目标时为 `init`，否则 `init` + `delta` × 连续次数，至多 `max`），写目标就改记这个目标，写倍率就改成给出它的次数；`funnelMap`（目标的 id → `{ s, t }`）只有上次目标这一项，`t` 永远不是现在，写回一个映射时取其中上次目标的倍率；`doll`（替身在场：从切换到替身起，到它结束为止）与 `dollSwitching`（正在切换，去与回）从引擎傀儡师的相位（职业-15）读，写入没有作用，记一条缺口 `compat: trait.doll is not provided yet`（`dollSwitching` 同）。不在场的棋子，或特性里没有这个状态（没有蓄力、浮游单元、替身）的，这些项只是普通的值。技能结束事件里，引擎的蓄力已回到 0；浮游单元只数上次目标，见 DIF-0046。
- **钩子与计时**：用引擎的钩子与计时器（钩子-1…钩子-3）。传给 kit 的上下文换成 Stronghold 的形状：单位换成上面的样子，`tick` 的帧数换成秒数 `dt`；kit 给的秒数换成整帧（时间-2：`after(1)` 在 30 帧后，`every(0.5)` 每 15 帧）。伤害、状态与弹药的有序结算事件（钩子-3）给 kit 的上下文同 Stronghold 的：`damageCalculate`（同 `hit`）、`damageApplying`（另有可改的 `amount`）、`damageApplied`（`kind`、`amount`、实际扣去的生命 `hpRemoved`）、`statusApplied`（状态用 Stronghold 的名字，`duration` 为秒数、无期限为 Infinity，`value`，`entered`）、`ammoUsed`（`unit`、`left`、`skill`）。kit 自己发的事件（`battle.emit`，上下文里的单位已是 kit 看到的样子）原样交给处理函数，不再按引擎事件的形状改一遍。
- **出错**：kit 的工厂、安装、钩子处理、计时器抛出异常时，这一次跳过并记下（哪一步、哪名干员、消息），战斗照常进行——Stronghold 也这样隔离内容的错误。

- **v0.3.2 的结算调用**：伤害、治疗与生命流失除了原来按位置传参的写法，也接受 Stronghold v0.3.2 的请求对象（只传一个对象：`source`、`credit`、`target`、数量与伤害说明）。没有来源、只有归属（`credit`，或位置写法第四个参数里的 `credit`）的伤害是记在归属名下的无来源伤害（伤害-7 的 `sourceless`）；伤害有来源又另给了不同的归属，引擎表达不了，以缺口报错（生命流失见 兼容-7）。请求的闪避方式换成引擎的：不判定闪避为 `canDodge` 假，判定但不能取消（或不接受因闪避、落空而取消）为 `noDodgeCancel`（伤害-12）；不接受因抵挡而取消没有对应，照常可被抵挡。计算阶段为「预计算」的照常结算（引擎还没有来源计算的时点，两者相同）；「计算后」与成功后的回调（`onApplied`）以缺口报错（没有来源的真实伤害的「计算后」除外，见 兼容-7）。生命流失（`dealHPLose`，旧名 `loseHp`）可以带类型：物理、法术先按目标的防御、法抗（伤害-1…伤害-5，带请求给的穿透）减去，真实（默认）为已算好的量；之后按 伤害-10。元素损伤（`dealElementDamage`）按 Stronghold 的元素名（元素-2）。元素的回复（`healElement`，旧名 `reduceElement`）：给了元素就只回复那一种，否则每一种都回复这个量，到最大值为止，爆发中不回复，返回合计回复的量。单位另给出元素值的最大值（`gaugeMax`）。`hpDamage` 的处理函数用 attack 的 `reserveTransfer` 从这次伤害里预留一份给转移：按第一次预留时的伤害算比例，不超过剩下的，同一标签只一份，这次伤害减去它；全部处理函数之后，每份按预留的量和伤害的标签加上各转移的标签交给它的去处，同 Stronghold。kit 读到的 `_hooks` 按事件名答它有没有处理函数。

- **范围的两种判定**：`enemiesInKeys` 按碰撞体积（体积-5：普通敌人半径 0.1 的圆盖住的格子，巨大敌人的矩形）。攻击档案带 `rangeTiles` 时（谬因：kit 的 `trait.rangeTiles`，或引擎特性数据里的同名标记，都写进单位的 `profile`）改走格子判定，与 `enemiesOnTiles` 相同（所占格，体积-1、体积-2）。`foesInColliderRadius(x, y, r)`：普通敌人的中心距离不超过 r + 0.1（常量-6），巨大敌人仍按其矩形是否在 r 内（体积-3）。`unitsInGrid` 以单位所在格为锚（体积-1 的五成双），`rangeTiles` 时用格子判定，否则用碰撞体积；友方始终按所占格。`onFieldBoard(r, c)` 为地图内且近战或远程可以站立的格子（推断 INF-0352），不算格上有没有干员（那是 `isReservedTile`）。

- **棋子的基础属性**（`base`）：干员的棋子（部署前、两次部署之间也一样）的 `base` 是一份记录：部署中读引擎单位的基础属性，部署前读内容里这名干员的记录；另有部署费用 `cost` 和再部署时间 `respawnTime`，取内容的记录。kit 写进去的留在棋子上：属性在每次部署时放到那次部署的单位上，费用和再部署时间只是记着，不改牌组的规则（上面说了，部署费用与再部署时间仍按引擎的），每写一次记一条缺口：每个单位每个名字一次，`compat: base.cost is not provided yet`（`base.respawnTime` 同），见 DIF-0040。别的单位的 `base` 仍是引擎单位自己的，离场时为空。
- **元素槽**（`elem`）：单位各元素槽已填的量，按 Stronghold 的名字（`burn`、`neural`、`apoptosis`、`erosion`）：元素最大值减去引擎里这个元素的值（元素-1，没有记录就是最大值）；坏死 `necrosis` 引擎没有对应，恒为 0（推断 INF-1094）。上场的先后读 `aggroSeq`（后上场的大）。
- **攻击档案可写**：kit 可以给单位换一份档案（`unit.profile = …`，设为空即取回）或写档案里的一项（`unit.profile.funnel = …`），对它之后的每次部署都算数；别的单位（召唤物、敌人）写的也记着。引擎自己的攻击不读单位的档案：兼容层读的是选目标和可否选中的那几项（`maxTargets`、`priority`、`allInRange`、`hitAllBlocked`、`canHitFly`、`groundOnly`、`hitSleep`、`skipEnemy`、`rangeTiles`、`attackRangeRadius`，索敌-2），kit 把档案交给兼容层的选目标函数时用上；和有浮游单元的单位的 `funnelMul`、`funnel`：`funnelMul` 写成空（或 false）即关掉这个单位的浮游单元——攻击的倍率不乘它、也不计数——，`funnel` 写成新的 `{ init, delta, max }` 即换上这组数，引擎每次攻击经特性行为（职业-6）问它们；有浮游单元的单位，档案里的 `funnelMul` 是一个函数（推断 INF-1104）。这些以外的项——`atkScale`、`hits`、`splashRadius`、`shockTimes`、`auraRatio`、`selfHeal`、`heal`、`dmgType`、`noAttack`、`dmgMul` 等，没有浮游单元的单位的 `funnel`、`funnelMul`——记着、不使用，每个单位每一项记一条缺口 `compat: profile.<项> is not provided yet`（只记值真的变了的项：整份档案展开后原样交回的不记），见 DIF-0038。档案的内容：干员（部署前的棋子也一样）的特性数据（`canHitFly`、`heal`、`dmgType`、`hits`、`rangeTiles`、浮游单元的 `funnel`、命中状态 `onHitStatus`），其上是 kit 自己的 `trait`（Stronghold 用它覆盖职业的档案），再其上是 kit 写的。单次攻击的档案（`beforeAttack` 与命中事件里交给 kit 的那份拷贝）不在此列，它的 `atkScale`、`afterHit` 照常用（兼容-5）。`removed` 可以写，什么也不改：kit 写 `false` 是让棋子留在原地，而棋子在这里永远不是被移除的（它可以再次部署），所以写入没有要做的事。
- **增益对象**：`addBuff` 返回给出的增益——同名替换或叠入时是在效果中的那一份，单位不在场时为空——；kit 读到的增益对象，每份增益从头到尾是同一个对象，带它第一次被 kit 看到的先后 `seq`（Stronghold 的获得次序）。`removeBuff` 给增益对象时只去掉这一份，给键时去掉这个键的全部，给空什么也不做。
- **增益的伤判**：kit 增益的伤判回调 `injury`、`observeInjury` 与固定减伤 `damageReduction` 在引擎的伤判里（伤害-8）轮到这个增益时运行，轮次按 kit 给的 `injuryPriority`（引擎的事件优先级）再按获取顺序。伤害还剩时：先是减伤——按伤害类型减去一个数，不低于 0；同一名字（`reductionGroup`，没有则为增益的键）的只最大的那份减，同样大取先轮到的，不同名字的都减——，再是 `injury`：它可以改 `amount`，可以 `dodge(p)`、`block(p)`（不给概率为必定；概率从这局的随机数抽，同 Stronghold），可以 `defer` 一个回调；之后 `observeInjury` 看到剩下的量、是否取消（`cancelled`）和结果（`outcome`：`dodged`、`blocked`、`zero` 或空）。闪避取消伤害时就是引擎的闪避：`dodge` 事件和闪避计数（伤害-8）；不可闪避的伤害不判定，无视闪避的照样抽、抽中也不取消（伤害-12）；伤害说明的 `ignoreCancelReasons` 含 `block` 时，抵挡判定成功也不取消。更早的效果已经取消伤害时，这个增益只调用 `observeInjury`（剩下 0，`cancelled` 为真）。回调抛错记在给增益的单位名下（没有给的为持有者），伤判照常进行。kit 的护盾层数、屏障与它们吸收的类型是引擎的护盾与屏障（见「屏障与护盾层」）；只剩用完的护盾、因此被移除的增益，调用它的 `onRemove`（伤害-8 的 `spent`）；kit 可读写增益的 `shieldHits`。用完仍保留的空护盾（`keepEmptyShield`）引擎还没有：增益照给，每个单位每个键记一次缺口（标签 `buff.keepEmptyShield`）。与 Stronghold 次序上的不同见 DIF-0041。kit 用敌人或无来源打出的伤害也带着内容结算，增益的伤判同样运行。

### 兼容-5 kit 的技能说明

kit 为技能写的说明（Stronghold 的 SkillSpec）接到引擎的技能运行上：

- **接法**：kit 说明过的每个技能，按技能 id 登记一个引擎的技能行为（技能-6，ADR 0055）。同一技能 id 的干员，有 kit 说明的按说明运行，没有的仍按引擎从数据生成的通用效果（技能-5）。登记了行为的技能不再有通用效果，所以 kit 的效果不会与之重复。
- **何时发动**：照引擎的规则（技能-3）——手动技能由玩家发动，自动技能按它自己的时机——，再加上说明的 `trigger`（规则名，或 `{ rule, grid, allies, hpAtMost, enemies }`），按 Stronghold 的 SkillRuntime 读；技能行为的 `trigger`（技能-3）据此回答：
  - `NEVER`、`MANUAL`，以及格子为空的 `CUSTOM_RANGE`（kit 声明「引擎不要自己发动」的写法）：不自动发动，kit 自己用 `skill.activate()` 发动（塞雷娅的二技能、缇缇的二技能；Stronghold 同样永不自动发动）；
  - `SP_FULL`（`ALWAYS`）：技力一满就发动，不等攻击；
  - 带格子的 `CUSTOM_RANGE`：格子（facing-right 的 [行, 列] 偏移，按干员所在格与朝向，索敌-1）上有它能选中的敌人时就绪即发动，没有就不发动；`SKILL_RANGE` 同样，只是任何活着的敌人都算（无视不可选中）；带 `allies` 的 `SKILL_RANGE`：格子上有生命比例不高于 `hpAtMost`（缺省 1）的受伤友方时就绪即发动，没有就不发动；
  - `DEFAULT`、不认识的规则、没有格子的 `CUSTOM_RANGE` 与 `SKILL_RANGE`：基础规则，发动的时机仍是引擎的；带 `allies` 时另要求格子（没有格子则干员的攻击范围）上有这样的友方，没有就不发动；治疗技能（说明写 `heal: true`，没写时干员的特性是治疗）另要求攻击范围里有受伤的友方（`trigger.enemies` 时敌人也行），没有就不发动（推断 INF-1095、INF-1096、INF-1097）；
  - 说明没有 `trigger` 的技能，也不是治疗技能的：没有意见，照引擎的规则。
  - kit 在战斗中用 `setTrigger(规则, 格子)` 改的规则与格子，从那时起取代说明里的（空格子算没有格子；`allies`、`hpAtMost`、`enemies` 仍取说明的）。
  - 不读：kit 另加的触发范围（`addTriggerRange`，只记着，可由 `triggerSatisfied` 查询）和 `TAKE_DAMAGE`、`ACTIVE_RANGE`、`SEARCH`、`GDGLOW_SKILL_2` 等规则，它们按基础规则；数据里的触发规则也不读，引擎的技能记录没有（DIF-0042）。
- **运行中**：说明的修饰器与标记在技能运行时作为一个增益加在干员身上（修饰键与标记名见 兼容-4）；开始、每帧、结束时调用说明的 `onStart`、`onTick`、`onEnd`——结束时先调用 `onEnd`（此时修饰器仍在；上下文带结束原因 `reason`，同 skillEnd 事件，技能-6），再去掉增益。技能的发动次数（`activations`）在调用 `onStart` 之前加 1，同 Stronghold。
- **类型与时长**：说明的类型为 `duration`、`toggle`（可关闭的持续技能）、`ammo`、`passive` 时，引擎按它计时（技能-6 的 `timing`），说明写了 `duration` 时持续这么多秒；`instant` 与 `charges`（可充能的 instant）在说明带自己的攻击时是下次攻击技能，否则沿用技能记录的类型。
- **攻击**：有说明的技能运行时，普通攻击从干员自己的攻击起算（倍率、段数、目标数都为 1，blackboard 的攻击键由说明自己读取），再加上说明的攻击覆盖（技能-5）：倍率（数字形式的 `dmgMul` 再乘上去，作用于整次攻击）、每次攻击的段数、目标数（`allInRange` 为范围内全部）、伤害类型或治疗、每段命中给的状态；函数形式的 `dmgMul(battle, unit, target)` 按目标给主目标的倍率，在防御之前乘到这次伤害上，并取代特性对这个目标的倍率（职业-8、职业-11），同 Stronghold 技能档案取代职业档案；`hitsFn` 返回 0 时这次攻击本身不对主目标造成伤害（命中在最前取消，其后的 `hit` 处理不再调用），命中回调照常以 0 伤害调用；这两项只作用于引擎攻击的命中，kit 自己造成的伤害不受影响；`attack.noAttack` 时技能期间不进行普通攻击（职业-13 的标记）。kit 看到的 `isSkill`（命中的伤害、`attack` 事件、命中回调、回旋投射物的回调）只在说明改了这次攻击或索敌（有 `attack` 或 `targeting`）时为真：只给修饰器、没有攻击与索敌覆盖的持续技能，期间的普通攻击对 kit 仍是普通攻击，同 Stronghold 的 effectiveProfile 只在有覆盖时标 `isSkill`；引擎自己的 `isSkill`（钩子-3：技能运行时或技能造成）不变，说明不在的技能也仍是引擎的；`beforeAttack` 与 `boomerangCaught` 事件里的 `isSkill` 也仍是引擎的（DIF-0043）。
- **命中与攻击之后**：引擎在一次攻击对每个目标的各段伤害结算后发 `attackHit`（引擎自己的事件，带合计伤害与类别：主目标、溅射、跳跃、余震）。技能运行时，或命中来自技能自己的攻击时（下次攻击技能的弹道在技能结束后才命中），每个受击者调用说明的 `attack.onEachHit`；主目标再调用 `attack.onHit` 与 `onHit`。一次攻击结算后（`attack` 事件）调用 `onAttack`，它把 `noAmmo` 设为是时这次攻击不耗弹药。引擎的命中不带它属于哪次攻击：对同一目标，`attackHit` 之前的各段命中（一次多段的攻击）是一次攻击；秘术师随这次攻击放出的储存能量弹，在同一帧作为各自的命中落到同一目标，也算这次攻击（推断 INF-1098、INF-1099）。每次攻击对一个目标，主目标的 `onEachHit`、`afterHit`、`attack.onHit` 与 `onHit` 只调用一次，档案的 `dmgMul` 与 `hitsFn` 也只问一次，答案对这次攻击的每一段命中都算——同 Stronghold 的 resolveHit 一次（随机数也只取一次）；这次的调用在第一段命中之后，`dealt` 只是它的（DIF-0044）。
- **kit 自己的特性档案**（kit 的 `trait`，Stronghold 用它覆盖职业的档案，技能运行时说明的攻击再覆盖它）：每次攻击都按它——能否攻击（`canAttack`）、没有目标时储存能量（`storeEnergy`）与对哪些友方无视禁疗（`healThrough`，伤害-13）经分支的特性行为（职业-6）；主目标的段数为 0 时取消这次命中，`dmgMul` 取代特性的倍率；`onEachHit` 对每个受击者、`afterHit` 在主目标之后、`afterAttack` 在一次攻击之后调用；技能说明的攻击给出伤害类型、没有声明治疗时，技能运行期间治疗干员的攻击改为攻击敌人（Buff 标记 `attackFoes`，职业-2；同 Stronghold 去掉档案的治疗）。kit 的特性替换了职业档案里引擎以特性数据表示的部分时，干员的特性数据随之改变：`afterHit` 取代投掷手的余震（Stronghold 唯一的职业 afterHit），`splashRadius` 取代溅射半径，`onHitStatus` 换掉每次命中给的状态（写空、或没有时间的，就没有；技能运行时引擎另给技能攻击的状态，DIF-0047），`hits` 与 `hitDmgMul` 是每次攻击的伤害次数和每次伤害的份额（职业-3：算过防御之后乘，第二次起不给受击回复），`maxTargets` 是最多的目标数，`noAttackUnlessSkill` 让它只在技能运行时普通攻击（职业-12；自动技能一就绪就发动，推断 INF-1101），`hitSleep` 让它选得中、打得中沉睡的敌人（职业-28），`rangeTiles` 按敌人所在的格索敌（体积-5），`blockFly` 让它能阻挡飞行单位（阻挡-2），自己有 `install` 的特性取代职业的安装——吟游者的生命回复光环随之去掉，由 kit 自己给——，傀儡师的替身不带引擎对替身的模组追加（攻击与生命的加成是 kit 的，推断 INF-1103），`dollNoAttack` 让替身不进行普通攻击。kit 的特性里别的项（`priority`、`heal`、`dmgType`、`noAttack`、`funnelMul`……）兼容层不认，每个棋子每一项记一条缺口 `compat: trait.<项> is not provided yet`，不再静默丢掉，见 DIF-0045（`rampInit`：引擎从模组的数据取同一个值）。Stronghold 没有职业规则、由 kit 自己实现特性的分支，引擎特性里相应的部分交给 kit：塑灵术师对自身召唤物阻挡的敌人的倍率（职业-14）取 1，由 kit 自己乘到命中上。kit 自己实现它那名干员的模组（Stronghold 的 kit 写明「the trait and both modules」），模组追加的特性也在内：带 kit 的干员不带引擎的模组追加特性（职业-17 的按目标倍率、职业-18 的条件增益、职业-20 的命中附带与光环、职业-21 的召唤物加倍）。部署、撤退与部署位的规则（职业-21 的首次部署费用、首次撤退的再部署时间、撤退返还、不占部署位的召唤物）仍是引擎的：Stronghold 没有部署费用（op-siege.js 写明 SOL-Y「首次部署时部署费用-4」在那里没有效果）。投出回旋投射物的那次攻击的档案（技能的攻击投出的用技能说明的，否则用 kit 的特性）有 `boomerangOnward` 时，投射物到达目标后由它接管（引擎的 `boomerangHit`，职业-12），同 Stronghold：上下文有 `home()`（干员仍是投出时那次部署）、`hit(目标)`（用这次攻击打另一个敌人）、`comeBack(x, y)`（从那里送回，只一次，返回回程的 `x`、`y` 与干员的位置 `tx`、`ty`）；它出错时投射物从命中处返回。它自己的 `install` 在天赋之前运行，并接管分支的部署效果（特性的增益与维持消耗不再由引擎给，同 Stronghold 的职业安装让位于它；攻击方式——子弹的倍率等——照常）。kit 的天赋在 kit 自己的 `install` 之前安装，同 Stronghold。
- **技能运行时的读写**：kit 读技能的有无、类型、是否运行、技力与充能、剩余时间与弹药、发动次数（整局累计）；可以直接设定技力，免费或照常发动、结束技能（原因同 Stronghold）。

- **棋子 kit 的默认技能**：棋子 kit 的 `skill` 是这个棋子默认技能的说明。kit 在 `skills` 里按技能 id 写了说明的，按 id 取；没写、而 kit 是棋子 kit（工厂带 `chess` 标记，宿主用 `chessKit` 标）时，所选技能取 `skill`；不是棋子 kit（干员 kit 把每个支持的技能都写在 `skills` 里，默认技能不代表别的技能）或没有 `skill` 时没有说明，技能按引擎自己的（技能-5）。Stronghold 的 `selectSkillSpec` 在所选技能是棋子的默认技能时取 `skill`；引擎的记录没有这一标记，所以棋子 kit 在 `skills` 里没写所选技能时一律取 `skill`：v0.4.0 的棋子 kit 把默认技能以外的技能都写在 `skills` 里，默认技能不会套到别的技能上（推断 INF-1092）。
- 来源：设计决定（手动技能由玩家发动：2026-10-12 的规划讨论，计划 E1d）；SkillSpec 的字段与调用时机取自 Stronghold 的 `docs/SIM.md` §7、`server/sim/skills.js`、`server/sim/ai.js`（GPL-3.0-or-later）；固定版本对照里推进之王的 kit 原样载入，三技能由玩家发动后攻击间隔 +1 秒、倍率 380%、命中时 40% 晕眩 1.5 秒，25 秒后结束；二技能在她攻击时自动发动，回 3 点费用、下次攻击倍率 340%（`packages/content/test/compat-skills.test.js`）；kit 特性各项取自 Stronghold v0.4.0 的 `server/sim/professions.js` 档案字段的说明、`server/sim/ai.js` 的 resolveHit 与 `server/sim/content/kits/ops/` 里各 kit 的 `trait`（GPL-3.0-or-later；`packages/content/test/compat-traits.test.js`，差分里有 7 个 kit 带兼容层不认的特性项，各钉一行缺口，`packages/content/data/kits.json`）；棋子 kit 默认技能的取法取自 Stronghold v0.4.0 的 `server/sim/content/index.js`（`selectSkillSpec`）；说明的触发规则取自 Stronghold v0.4.0 的 `server/sim/skills.js`（SkillRuntime 的构造函数、`tick`、`_tickRuleSatisfied`、`_defaultCondition`、`_allyTriggerSatisfied`、`setTrigger`，GPL-3.0-or-later），`isSkill` 取自 `server/sim/ai.js` 的 `effectiveProfile`，每次攻击只问一次取自同文件的 `resolveHit`（`packages/content/test/compat-triggers.test.js`）；2026-11-16 的整局实测里，129 个棋子 kit 的 258 个形态原来只有 2 个取到说明，补上之后 258 个都取到（`packages/content/test/compat-chesskits.test.js`）

### 兼容-6 对局里的 kit

固定版本的 Stronghold kit 作为内置的脚本 mod 在对局中运行（ADR 0058）：

- **清单**：`packages/content/data/kits.json` 记下固定提交（与差分对照同一个）、72 个干员 kit 各自的文件，以及启用名单——在小关卡冒烟运行中不报错、并通过逐个 kit 的差分对照的才启用。通过的意思是：所有技能与 Stronghold 一致，或者只差已登记的差异——这样的 kit 在清单的 `differences` 里按技能记下预期的每一行对照差异和背后的差异编号（DIF，仍有效的），CI 要求实际差异与记下的逐行相同，多一行、少一行或变了都不通过。
- **逐个 kit 的差分对照**：同一个 kit、同一练度（Stronghold 自选的精英形态：精英二 60 级、潜能 6、信赖 0、技能 7 级、最后一个模组 3 级），在 Stronghold 自己的战斗测试工具里和在我们的引擎里，各对着身前一个不会移动的假敌人（生命 1e7、防御与法抗 0；Stronghold 的移速为 0，我们这边用一个不是状态的增益定住它——「束缚」是 kit 会查看的状态；它不站在自己的路线上）跑 40 秒。两边是同一块场地：我们的关卡逐格照搬 Stronghold 这一局的战场（高台、出怪点与保护目标、可部署与通行），干员与假敌人站在同样的格子上。技能按 Stronghold 的自动操作发动：手动技能在这一局里当作同一时机的自动技能——即将攻击时，或（每帧检查的规则、不攻击的干员）一就绪就发动，带 kit 触发范围的在范围里有敌人时就绪即发动、否则即将攻击时；开局即可发动，此后两次之间至少 3 秒；Stronghold 这一局一次没发动的技能我们这边也不发动。kit 的随机数在我们这边取 Stronghold 同一种子的随机数序列（这个场景里没有别的东西取用它，kit 的每次取数两边相同；对局里 kit 用对局自己的随机数，随机-1）。比较：部署 1 秒后的增益（不含技能的、不改任何东西的；分支特性的增益——我们引擎的 `trait`、Stronghold 的 `trait:<分支>`——只比修饰器，标记在 Stronghold 的攻击档案里；Stronghold 把解放者的「阻挡数×0」写成阻挡数 −99，按 ×0 比较）、每次命中扣掉的生命（不含元素损伤）和每次治疗的量（取各不相同的值：任一边的每个值在另一边都有相差 0.5%（至少 1）以内的值，算相同——Stronghold 的属性取整，随目标生命变化的伤害两边取到的值也多少不一）、技能发动次数（相差不超过 1）、施加的状态（种类与秒数）、我们这边记下的 kit 错误。启用名单里的 kit 都必须全部一致（记下预期差异的除外，按上一条），CI 每次检查。
- **载入**：按对局里的干员，载入其中已启用的 kit，按角色 id 的顺序逐个载入（兼容-1 的载入网格）；载入不了的记下，那名干员按引擎自己的实现。Node 里从固定提交的目录载入（兼容-2 的加载钩子）；浏览器里从平台提供的、已按映射表改写导入的副本载入，浏览器端不改写。
- **对局内容**：有 kit 的干员用 kit（同一干员的几份各有一份，同步-9）：它的记录去掉天赋部分（天赋由 kit 施加；傀儡师替身的不攻击与光环也去掉，替身的范围保留，职业-16），它的队伍天赋不由引擎再给；kit 的每局挂接与技能行为（兼容-4、兼容-5）加进内容。内容记下固定提交与所用的 kit（按角色 id 排序），这一项计入内容哈希（同步-10）：两端载入的 kit 不同，就不开局。

- 来源：设计决定，见 [ADR 0058](../adr/0058-stronghold-kits-in-matches.md)、[ADR 0010](../adr/0010-import-mapping-table.md)；固定提交里 72 个文件各自导出它那名干员的 kit；载入推进之王后，她的对局内容不含天赋字段，部署后由 kit 给出两项天赋（`packages/content/test/compat-match.test.js`）；2026-10-15 的第二次全量对照（当时的对照是 v0.2.4）中 65 个 kit 的所有技能与 Stronghold 一致；其余 7 个各自的差异都来自已登记的差异（DIF-0001、DIF-0023、DIF-0030、DIF-0032、DIF-0033、DIF-0035、DIF-0036），按用户的决定记下预期差异后启用——72 个全部启用。钉到 v0.3.1 后重跑：这 7 条预期差异一行未变；澄闪三个技能的普通攻击在 Stronghold 侧多出一记不乘浮游倍率的本体伤害（DIF-0037，职业-12），记下后 72 个仍全部启用（`packages/content/test/compat-diff.test.js`）；kit 自己实现模组：固定提交里 op-crosly.js「the trait and both modules (EXE-X 弑君刃, EXE-Y 木炭画)」以 `trait:crosly:lonely` 实现 EXE-Y「周围四格没有友方干员时攻击力+10%」，op-shwaz.js 实现 ARC-Y、op-lin.js 实现 PLX-Y、op-mantra.js 实现 PRI-X

### 兼容-7 kit 以外的战斗内容：盟约

Stronghold 在 kit 之外还有一局战斗的内容模块（`server/sim/content/` 下的盟约、特质、装备、策略、召唤物、装置、敌人、首领、决策，各自导出 `install(battle)`）。兼容层让它们原样载入，并先接上盟约（第二期下半的 `bonds/core.js` 与 `bonds/addon/battle.js`；规程的 `bonds/regulation.js` 也载入，但只在其他版本的数据上安装，默认数据不走它）：

- **载入**：这些模块都经映射表（兼容-2）原样载入。替身另给出它们导入的名字：常量取 Stronghold v0.4.0 的值（`ATTACK_ANIM_TIME`、`BLOCK_RADIUS_SQ`、`BOSS_ROW_OFFSET`、`ALLY_COLLIDER_RADIUS`、`STEALTH_RESTORE`、`MAX_ALIVE_ENEMIES`、元素爆发表 `ELEMENT`，以及 Stronghold 棋盘的几何 `GEO`——我们的关卡大小各自不同，内容只在它的首领战场与准备阶段读它）；方向的 `DIR_VEC`、`oppositeDir`、`localBefore` 用引擎自己的（方向-1）；`extendedGrid`（攻击范围扩大的相对写法，最多到关卡宽度）、`birthCellTargets`、`birthLocalTargets`、`isPotential` 用 Stronghold 的写法移植；敌方选择我方的规则（`canTargetAlly` 等）、路线与数据视图（`compileRoute`、`normalizeRoute`、`withUnitLoadouts`、`isShopItem`）先作缺口。
- **数据**：内容读的游戏数据是 Stronghold 自己的（同一份检出的 `data/*.json`，按文件名），由宿主在内容读它之前给出一次（`setShData`）；没有给出时读它是缺口。战斗对象的 `data.raw` 是这份数据；原始的敌人记录（`data.rawEnemy`）是缺口。
- **宿主**：一局的内容（`matchContent`）带上这些：各座位的输入、按顺序安装的模块，以及每造出一场战斗就交给它的回调（宿主由此读到战斗中加的层数）；没有 kit 时也一样装上。没有给出时，内容里没有这一层。模块由 `loadContent` 从宿主指定的检出载入：每个是 `server/sim/content/<名字>.js`，按给出的顺序（默认是 Stronghold 的安装顺序：tokens、devices、enemies、bosses、bonds、garrisons、items、bands、choices），同 kit 一样在载入网格下（兼容-1）；载入失败或没有 `install` 的列出名字，不装。模块导出 `kits`（`tokens` 模块：各召唤物的 kit，按召唤物 id）的，连同模块留着。
- **输入**：每个座位给出 Stronghold 一局战斗的玩家输入中内容读的部分：各盟约的实时状态（人数 `count`、是否激活、达到的档位 `tier`、层数 `layers`）、分队、各干员在引擎记录里没有的事实（棋子 id——精锐的以 `_b` 结尾，盟约、商店的阶、是否精锐、携带的装备、特质——放在定义的 `garrisonIds`，Stronghold 的特质从这里读；棋子 id 与是否精锐也在 kit 收到的棋子记录里：`chessId`、`baseId`、`isGolden`，kit 读 `chess.isGolden` 来装精锐的模组效果）、准备阶段交来的事实（`contentInfo`）、规程的效果替换。
- **召唤物的 kit**：`tokens` 模块的 `kits`（宿主要把 `tokens` 放进给出的模块里）给每个召唤物它的 kit：`spawnToken` 没有给 kit 的，用模块里这个召唤物的（Stronghold 的战斗对每个造出的召唤物都按这个找，没有时才用通用的）：以召唤物的定义造，装上同 `spawnToken` 给的 kit 一样（兼容-4：技能说明、天赋与 `install`，先于它的部署的一切处理）；只对有 kit 的干员的召唤物这样，别的干员的召唤物是引擎自己的（DIF-0052）。模块里没有它的 kit，或造 kit 时抛出异常的（记下），召唤物没有 kit。
- **棋子与安装**：有了这些输入，牌组里每名干员都有棋子（有 kit 的同 兼容-4，没有的也一样，从引擎的预留取 id），棋子的定义带上它的事实（kit 的工厂收到的就是带事实的定义）；装备在棋子上（`items`）。kit 都装好之后，按给出的顺序安装每个内容模块（同 Stronghold 的 installContent：先 kit，后各领域模块），这时还没有任何部署；安装出错时记下（兼容-4），战斗照常进行。
- **玩家**：战斗对象的 `players` 与 `getPlayer` 给出每个座位：玩家 id 即座位，不镜像，朝右，实时的盟约状态（输入的副本，战斗中的加层改它）、分队与输入，现有的费用和它的单位。战斗是 Stronghold 的普通战斗（`kind` 为 normal，无模式），战斗中加层开启（`flags.layerGainsEnabled`），战场是整张关卡（`rect`）。
- **战斗中加层**（`addLayers`）：先发 `layerGain` 事件（玩家、盟约、层数、原因、来源与它的格子——来源在场，或正是这一刻离场；处理函数可改层数，改成不是正的有限数即取消），再加到实时状态上，每个盟约至多 999 层（推断 INF-1090；已满时不发事件）；这一局加的层数另记下（`layerGains`）。加层关闭或不是这一局的座位时不加。规程的临时层数（`addTempLayers`）另记，不发事件，至多 1 万。
- **立刻重新部署**（`redeploy`）：在我们的模式里由玩家部署干员，所以按官方对它的解释（PRTS：「令受益者下次部署的再部署时间和费用归零」）：离场的（或正在离场的）干员的棋子，下一次部署没有再部署时间，`free`（默认）时也没有费用（这张牌自己的减费，部署-10，部署时用掉；别的干员部署时按 `deployCut` 把它压到自己的上限，随后再定回来）；同一次离场再给一次时不再给。在另一格再部署、保留技力的（突袭的跳跃）是缺口；突袭跳跃前的撤退（原因 `raid`）也以缺口报错，什么都不做——Stronghold 撤退后立即在别处部署，引擎还做不到。倒地的干员（`isDown`）在这些模式里没有，同 兼容-4。
- **再部署时间与技力消耗的倍率**：干员离场时，它的持续增益（`persist`，Stronghold 读之前去掉了其余增益）里的 `redeployMul`（如助力）连乘（各按层数次方），引擎设好它的再部署时间之后乘上去；内容设定技能的 `spCostMul`（绝技）时，技力消耗为技能的消耗 × 倍率向下取整，之后每次部署都按它（技力条上限为消耗 × 充能数，技力不超过上限）。技能另给出技力的回复方式（`spType`）。
- **单位**：内容另读到：棋子从不算永久离场（`removed` 为假，它还会再部署；其他单位离场即是）、上次离场的原因与时刻（`removeReason`、`deathAt`，引擎的 `death` 事件）、这次部署中上次攻击的时刻（`lastAttackAt`，每次部署从无开始）、可以再部署的时刻（`respawnAt`：离场时按它的牌定下，下次离场前不变——立刻重新部署也不改它；被击倒的 `death` 事件里引擎还没定下它的牌，读到无穷大。内容可以改它，离场的棋子的牌随之改，改成不是有限数的是缺口；在那个事件里改的，等牌定下后生效）、它的玩家（`player`），寒冷时的标记 `cold`（引擎的寒冷状态带它，状态-5；对寒冷免疫的单位没有，状态-7）。部署事件的 `initial` 在战斗开始（`battleStart`）之前为是，同 Stronghold 的开局部署。
- **结算的补充**：伤害说明可由 `makeDamage` 造出（物理、量 0、倍率 1、无标签，再加上给出的）。「计算后」（已过防御与来源倍率）的伤害只有没有来源（或无来源）的真实伤害可以结算——这时它就是原数（坚守的分担）；其余仍是缺口。有来源又另给了不同归属的生命流失记在归属名下（击杀与统计归它，同 Stronghold，如阿戈尔的吞噬：来源是被吞噬者自己，归属是标记它的干员）；引擎的来源与归属是同一个单位，所以事件看到的来源也是归属。
- **还不会发出的事件**：盟约用到、引擎不会发出的 `dollSwap`（不屈对傀儡师切换的判定），处理函数不会被调用；`ammoUsed`（拉特兰 6 人的弹药加攻）、`statusApplied` 是引擎发的（钩子-3）。
- **第二期下半的盟约**：核心盟约（炎、萨尔贡、维多利亚、谢拉格、拉特兰、阿戈尔、叙拉古、卡西米尔）与加成盟约的战斗效果按 Stronghold 的数据安装，随层数变化的在战斗中加层后的下一帧开始时跟着变。其中有：炎、精准、坚守、助力、协防干员、独行、绝技、维多利亚的常驻增益与突袭到达层数后的攻速，萨尔贡的技能叠层，谢拉格的倍率与寒风，拉特兰的弹药，阿戈尔的吞噬与 5 人的复活，叙拉古的攻速与隐匿，卡西米尔的部署加攻，不屈的技力与重新部署，灵巧的光环，迅捷的技力，坚守的分担，奥术的法术易伤。炎 6 人的「炎佑」要读原始的敌人记录，突袭的跳跃要在另一格部署（见上），都是缺口，记为错误。

- 来源：设计决定，见 [ADR 0012](../adr/0012-stronghold-compatible-core.md)、[ADR 0058](../adr/0058-stronghold-kits-in-matches.md)（kit 以外的内容原样载入，只改写导入）；玩家状态、战斗中加层、立刻重新部署、开局部署的顺序取自 Stronghold v0.4.0（`b6d8b2ef`）的 `server/sim/Battle.js`、`server/sim/battle/players.js`、`economy.js`、`deploy.js`、`shared/constants.js` 的 `layerGainRoom`，盟约取自 `server/sim/content/bonds.js`、`bonds/core.js`、`bonds/addon/battle.js`，共用的帮手取自 `server/sim/content/support/index.js`，移植的名字取自 `server/sim/constants.js`、`server/sim/targeting.js`、`shared/loadoutRecord.js`、`shared/potential.js`、`shared/i18n.js`（GPL-3.0-or-later）；「立刻重新部署」的解释取自 [PRTS「卫戍协议：盟约 下半/PRTS盟约记录」oldid=449019](https://prts.wiki/index.php?title=%E5%8D%AB%E6%88%8D%E5%8D%8F%E8%AE%AE%EF%BC%9A%E7%9B%9F%E7%BA%A6_%E4%B8%8B%E5%8D%8A/PRTS%E7%9B%9F%E7%BA%A6%E8%AE%B0%E5%BD%95&oldid=449019) 不屈的备注「※“立刻重新部署”的实现方式为：令受益者下次部署的再部署时间和费用归零」（Stronghold `bonds/addon/battle.js` 也引用它）；每个盟约至多 999 层为推断 INF-1090；2026-11-15 测得 v0.4.0 的 23 个内容模块（`bonds.js` 等领域入口、`support/`、`tokens.js`、`devices.js`、`bosses.js`、`enemies.js`、`choices.js`、`index.js` 等）都能载入（未加时 12 个载入失败，另有 `bonds.js`、`bands.js` 吞掉了子模块的失败）；盟约的效果按其数据在小关卡里生效（`packages/content/test/compat-bonds.test.js`，需要 AUE_STRONGHOLD_DIR 指向 v0.4.0 或更新的检出；没有时跳过），兼容层自身的部分不需要检出（`packages/content/test/compat-content.test.js`）

### 兼容-8 kit 的敌人出手与麻痹事件

钩子-5 的两个事件给 kit 的上下文同 Stronghold：

- **`enemyAttackStart`**：`enemy` 和 `targets` 是 kit 看到的单位。kit 在这里让敌人晕眩、倒下（或 钩子-5 列出的别的情形）时，这次攻击取消。
- **`palsyTrigger`**：`enemy`；`buff` 是 kit 看到的麻痹增益（层数、剩余时间……，兼容-4）；`keep` 直接读写引擎的上下文，设为是时这一层不消耗。
- 固定版本（v0.3.1）的 72 个干员 kit 里，酒神的「堕梦」用 `enemyAttackStart`，真言的「噤声限域」用 `palsyTrigger` 和 `keep`。

- 来源：设计决定，见 [ADR 0057](../adr/0057-hook-bus-and-timers.md)（事件名沿用 Stronghold 的，兼容层把上下文转成它的形状）；上下文的字段与含义取自 Stronghold v0.3.1 的 `docs/SIM.md` §5、`server/sim/ai.js`（GPL-3.0-or-later）；固定版本里真言、酒神的 kit 原样载入，在小关卡中：麻痹打断敌人的攻击时真言的「噤声限域」按她当前的攻击力造成元素伤害，几率取 1 时不消耗那一层、取 0 时消耗；敌人的攻击落下时，酒神攻击范围内的敌人受到「堕梦」的神经损伤，它引起的爆发打断这次攻击（`packages/content/test/compat-morehooks.test.js`）
