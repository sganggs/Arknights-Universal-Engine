# Stronghold 兼容层

兼容层只在 `packages/content/src/compat/` 里（ADR 0045）。kit 的源码不改，只由导入路径映射表把它们的导入指向我们的模块（ADR 0010）。

### 兼容-1 网格尺寸

Stronghold 的常量模块把网格的列数 `COLS`、行数 `ROWS` 给成固定的数；我们的地图大小每关不同。

- 映射表把 kit 对常量模块的导入指向兼容层，其中 `COLS`、`ROWS` 是活的绑定：运行一场战斗的内容代码时（`withGrid`），它们是这一关的宽和高；之后恢复成之前的值，内容代码抛出异常或两场战斗的代码嵌套时也一样。
- kit 在函数里读 `COLS`、`ROWS`（编码、解码格子键，边界检查，遍历网格），每次调用读到的是当时这一关的尺寸。
- 在模块加载时就读的，值固定在加载那一刻。所以兼容层加载 kit 时，`COLS`、`ROWS` 都是 64（`LOAD_GRID`），大于任何关卡（数据里最大 50 × 44）：按地图大小生成的「整行」「整图」列表覆盖每一关，地图外的格子在算攻击范围时去掉（索敌-1）。固定提交的 Stronghold 内容代码里只有一处这样取值：`kits/ops/chess_char_4_20-fartth.js` 第 11 行的 `LINE`（远牙三技能的无限直线范围）。

- 来源：设计决定，见 [ADR 0010](../adr/0010-import-mapping-table.md)（只改写导入路径，不改 kit 源码）、[ADR 0012](../adr/0012-stronghold-compatible-core.md)、[ADR 0045](../adr/0045-unit-field-ownership-compat-isolation.md)；用法统计：ArknightsGameData 的 3943 个关卡中地图最宽 50、最高 44；固定的 Stronghold 提交中 83 个文件引用 `COLS` / `ROWS`（内容代码 66 个），按语法树分析，内容代码在加载时读取的只有上面一处（`packages/content/test/compat-grid.test.js`，ADR 0056）

### 兼容-2 映射表与 kit 的载入

- **映射表**：Stronghold 的 kit 所及的每个引擎模块（按它在 Stronghold 仓库里的路径）对应兼容层里的一个替身模块：`server/sim/` 下的 constants、detmath、dir、targeting、body、damage、buffs、ai、professions、simdata，以及 `server/data.js`、`shared/constants.js`、`shared/potential.js`，和 `shared/plugins/` 下的 steps、textNumber、limits、officialBounds、rules，共 18 个。steps、textNumber、limits 是 Stronghold v0.3.1 的原文件（没有引擎依赖，原样载入，放在同一目录并互相引用）。officialBounds 的原文件超出源码限制（`visit`、`appendFactionBounds` 的复杂度，`boundMessage`、`exceed` 的参数个数），映射到冷缓存替身：没有装入官方数据快照，读数与原文件在缓存为空时相同——没有官方最大值，计数上限是下限 64，步长不把亚帧间隔抬到一帧。rules 的原文件没有引擎依赖，但 `grantedBondsByMorph` 的复杂度超出源码限制，映射到只导出这个函数的替身，判定与原函数相同：官方模式下少于两件不给盟约，必须有一件能给出盟约的装备，其余装备的 `giveBondId` 在 `bondOk` 通过时给出，plus 模式一件即可且只给最左一件。内容文件（`server/sim/content/` 下：kit、它们共用的帮手、召唤物与道具模块）原样载入，只把它们对引擎模块的导入换成替身。映射表里没有的引擎模块被导入时报错，kit 新增的依赖立刻显出来。
- **加载钩子**：Node 的加载钩子由映射表生成，给出 Stronghold 仓库的根和兼容层的目录，就按表改写 Stronghold 文件里的相对导入。
- **替身**：
  - 纯函数直接给出：方向（按名字的四个朝向，朝右写的偏移每步转四分之一：右 (dr, dc)、上 (dc, −dr)、左 (−dr, −dc)、下 (−dc, dr)；第 0 行在最下，上为行号增大，与 方向-1 一致；不出现 −0）用 Stronghold 的写法移植；确定性数学用引擎自己的（与它逐位一致，数值-2…数值-5）；常量中 `COLS`、`ROWS` 按 兼容-1，`TICK` 为一帧（时间-1），其余先取 Stronghold v0.2.4 的值，用到它们的 kit 与对照比较时逐个核对。增益的合计（buffs 的 `aggregateMods`：同名修饰加算 × 层数，`…Mul` 连乘至层数次方，闪避按独立概率合并）与攻击档案（ai 的 `effectiveProfile`，兼容-4）也用 Stronghold 的写法移植。持续效果的伤害说明（damage 的 `periodicDamage`）为记在来源名下的无来源真实伤害（伤害-7），不可闪避，带 `dot`、`periodic` 标签。记录在某一潜能下的样子（potential 的 `atPotential`）就是记录本身：我们的记录本来就按所选潜能造出（兼容-3），没有 Stronghold 记录里的潜能注记。
  - 还没有提供的名字以「缺口」存在：kit 载入时它在，被调用时报错并写明模块和名字，不会悄悄做别的事。
- 固定版本的对照（Stronghold v0.3.1）里 72 个干员 kit（`kits/ops/op-*.js`）都原样载入；129 个棋子 kit（`kits/ops/chess_*.js`，卫戍协议的棋子，Stronghold Protocol 的 aue 分支用）也都能载入。

- 来源：设计决定，见 [ADR 0010](../adr/0010-import-mapping-table.md)、[ADR 0012](../adr/0012-stronghold-compatible-core.md)；方向的写法取自 Stronghold 的 `server/sim/dir.js`（GPL-3.0-or-later）；插件模块取自 Stronghold v0.3.1 的 `shared/plugins/`（GPL-3.0-or-later），officialBounds 为冷缓存替身、rules 为 `grantedBondsByMorph` 替身，见上；v0.2.4 的导入闭包按语法统计是 72 个 kit、9 个共用内容文件、引擎模块 13 个、61 个名字，棋子 kit 另用到 6 个名字（常量 `CHAIN_RADIUS`、`ELEMENT_GAUGE_MAX`，取固定提交的值；`powi` 用引擎自己的；`attackCountdown`、`applyRedirectCut`、`redirectShare` 先作缺口）；钉到 v0.3.1 后映射表为 18 个（kit 载入闭包另及 `shared/plugins/rules.js`）

### 兼容-3 kit 的输入：记录与定义

kit 的工厂收到 `(bb, chess, def)`：所选技能的 blackboard、这名干员的记录、规范化后的定义。兼容层用引擎自己的练度数据（干员-1…干员-7）造出它们，形状同 Stronghold 的「自选」记录，但练度任意：

- **身份**：干员 id；所在的「槽位」写作 `aue_<干员 id>`。
- **属性**：这一练度下干员自己的属性（精英化与等级、信赖、潜能、模组的加值），不含天赋的效果——天赋由 kit 自己施加。部署费用、阻挡数、攻击间隔、再部署时间等照搬；技力回复为每秒 1。
- **范围**：这一精英阶段的攻击范围；**特性**：已解锁的最后一个特性 blackboard，模组改写特性时用模组的值覆盖（干员-7）；模组只作展示的特性部件（`DISPLAY`，追加一行说明）带的 blackboard 也并入，同 Stronghold 的记录（这一行的效果游戏里由隐藏天赋给出，kit 从特性读它）。
- **天赋**：每个天赋已解锁的最后一项；模组改写天赋时，模组的值覆盖、天赋原有的其余键保留，改写不属于任何天赋的（序号 −1，如攻击范围）另加一条。
- **技能**：这一精英阶段已解锁的每个技能在所选技能等级上的数据；所选的那个作为 `skill`。
- **技能范围**：kit 技能说明的 `targeting.rangeGrid`（朝右写的 [行, 列] 偏移）是技能运行时的攻击范围（技能-8），按这时的内容读——kit 在开始时原地重算也照用（司霆惊蛰 S2 的低地洪水填充）；没有时用记录的范围。
- **说明文字**：技能、天赋、模组的天赋改动和召唤物的说明同 Stronghold 的记录：占位符（`{key}`、`{-key}`、`{key:0%}`）按 blackboard 代入，`desc` 去掉官方的富文本标记，`descRaw` 保留标记（kit 会从说明里读数，如望的「最多拥有8（+1）枚」）。
- **模组**：所选模组及等级；没有时为未装备。另列出这一练度下已解锁的每个模组，各在所选模组等级上：平加的属性、特性（不改写特性时为空）、天赋改动——都按模组自己写的值（一个天赋部分里已解锁的最后一项，即潜能对应的那一档），不与天赋合并。
- **不带模组的记录**：属性、特性、天赋各再给一份不带模组的（`statsBase`、`traitBase`、`talentsBase`）。kit 用它们分开天赋本身与模组的追加：推进之王的「万兽之王」在模组「糖果盒」3 级下，给全体先锋的取天赋本身的 +10%，自身额外的 +8% 取模组的改动（合并后的天赋里两者同名，只剩 8%）。
- **定义**：记录按 Stronghold 的规则规范化，再带上所选技能、模组与潜能。
- **召唤物原始记录**：战斗对象的 `data.rawToken(id)` 给出召唤物在其召唤者练度下的记录（这局里第一个持有它的棋子的），场上上限另放在顶层，同 Stronghold 的 tokens.json；没有棋子持有它时为空。

- 来源：设计决定，见 [ADR 0016](../adr/0016-arbitrary-operator-levels.md)（任意练度在数据层计算）；记录的形状与规范化、天赋的合并规则取自 Stronghold 的 `server/sim/simdata.js`、`shared/loadoutRecord.js`（GPL-3.0-or-later）；模组选项的字段（`modules[]`、`…Base`）同 Stronghold 的数据说明 `docs/DATA.md` §2.2；72 个 kit 在每个技能（精英二满级、最后一个模组 3 级）与精英零、精英一 1 级下都能由这些输入造出 kit


### 兼容-4 战斗里的 kit

kit 在战斗里看到的是 Stronghold 的战斗对象；兼容层用引擎的世界给出它（`packages/content/src/compat/battle.js`、`unit.js`、`skill.js`、`kits.js`）：

- **挂接**：内容的开局挂接（钩子-4）造出这局的战斗对象；牌组里每个有 kit 的干员得到一个「棋子」，整局一个，同 Stronghold 的棋盘棋子。棋子的 id 也整局不变：开局前从引擎预留（钩子-4 的 `reserveIds`，按座位、牌组顺序），部署前、两次部署之间都一样；按 id 找单位时它找得到棋子，其他单位用引擎的 id。开局前每个棋子的 kit 装一次：kit 自己的安装和各天赋的安装。
- **部署**：干员每次入场时（钩子-3 的 `enter`：它的特性、天赋、被动技能生效之前，同 Stronghold 先装好 kit 再启动被动技能），先于任何 kit 对这次部署的处理，把它的棋子绑定到引擎的单位上，再把它的持久增益重新给上。撤退或阵亡后棋子解绑，kit 装下的钩子与计时器留着，看得到之后的每次部署。
- **单位**：kit 看到的单位有 Stronghold 的字段与读取方式：位置、格子、朝向、生命、当前属性、阻挡的敌人、增益，都从引擎的状态现读。属性的标记另以 Stronghold 的名字给出（`invulnerable`、`bind`、`noHeal`、反隐 `reveal`），元素爆发中另有 `burstLock`。kit 自己存的状态（`mem`、`trait`）在兼容层，不在引擎的状态里（ADR 0057）。没有 kit 的干员和敌人也以同样的样子给出。kit 选友方时（光环、治疗、给增益）不选孤立的单位，自己除外。另有：部署时刻（`deployedAt`，战斗秒数）、在地面（`ground`：我方在地面格、敌方不在空中）、是不是领袖（`isBoss`）、距下次攻击的秒数（`atkCd`）；攻击档案（`effectiveProfile`）为它特性的档案，技能运行且说明有攻击或索敌覆盖时叠上这些覆盖（兼容-5）。战斗对象给出战斗秒数 `time`（这一帧开始时，帧 × 1/30，同一帧的处理里都相同）和是否已经结束（`finished`，结束-1）。朝向的一步（`fwd`，方向-1：向上为行 + 1）；额外攻击格（`extraRangeKeys`，战斗对象的 `setExtraRange` 设置，攻击-1）。
- **钩子与计时**：用引擎的钩子与计时器（钩子-1…钩子-3）。传给 kit 的上下文换成 Stronghold 的形状：单位换成上面的样子，`tick` 的帧数换成秒数 `dt`；kit 给的秒数换成整帧（时间-2：`after(1)` 在 30 帧后，`every(0.5)` 每 15 帧）。
- **出错**：kit 的工厂、安装、钩子处理、计时器抛出异常时，这一次跳过并记下（哪一步、哪名干员、消息），战斗照常进行——Stronghold 也这样隔离内容的错误。
- **场上的查询与动作**（`field.js`）：格子上、半径内可选中的敌人（索敌-2：在场有血、未消失，不是无法选中、隐匿生效（被阻挡时、恢复窗口中不算）、离场的；睡眠的只有能打睡眠的可选；飞行的只有能对空且不限地面的可选），某格上的友方单位，单位阻挡的敌人；造成伤害（伤害-7；干员造成的记击杀，职业-5；元素损伤记到目标的元素上，元素-2）、治疗（伤害-11）、生命流失（伤害-10，带 Stronghold 的标签）、撤退（撤退-1）、移动（`moveRedeploy`：部署-9 的保留方式，生命、Buff 和技能都保留，与 Stronghold 相同，见 DIF-0034；元素值回到最大值、元素爆发结束，固定版本的 Stronghold 两者都保留；Stronghold 拒绝的——离场的、目标格有别的友方——和引擎会改为撤退的都拒绝，不做任何事；`clearSp` 时先清空技力，运行中的持续技能除外；算一次新的部署）。伤害链、攻击、技能、状态的事件（钩子-3）给 kit 的上下文同 Stronghold：可改的数（`hpDamage` 与 `heal` 的量、`fatal` 的阻止、`beforeStatus` 的时长（秒）、数值与取消）直接改在引擎的上下文上；`beforeAttack` 的目标列表 kit 可以整个换掉，也可以原地增删，每个处理函数之后写回引擎。单位另有空中、能否行动、重量、阻挡它的单位、当前攻击范围的格子与职业的选择规则（能否对空）、增益列表等读取方式；攻击范围内可选的友方；格子上需要治疗的友方（生命比例低的在前）；格子是否已被占用；敌人剩余的路径距离（索敌-6）；放开单位阻挡的敌人（阻挡-3）；敌人地面路线经过的格子（`groundPathTiles`：关卡波次用到的非飞行路线——都没有指明时为全部非飞行路线——从起点经 MOVE、APPEAR_AT_POS 检查点到终点，各段为 寻路-2 的经过格子）；一次攻击会取的目标（ai 的 `acquireTargets`，照搬 Stronghold：治疗取范围内受伤的友方，生命比例低的在前；否则取范围内可选的敌人与自己阻挡的，`allInRange` 全取，否则按优先级取目标数个）；放开一个敌人的阻挡（`_unblock`，阻挡-3）；立即攻击（`forceAttack`：攻击-5，给定目标或它自己会取的，`noAmmo` 时不耗弹药）；kit 自己的投射物（`addProjectile`，照搬 Stronghold：追踪单位或飞向定点、按速度每帧移动，到达时调用 `onHit`；目标离场或重新部署时作废，`hitDead` 时落在最后已知的位置；最长 10 秒。它们是 kit 的状态，每帧在 `tick` 处理函数之前推进，暂不绘制）；半径内的友方（`alliesInRadius`，按中心，可限一名玩家）；推开（`push`：位移-2，`dir` 给方向，`fixed`、`fixedAngle` 免去修正，`inward` 朝推动者，`effect` 为特效类；之后的失衡滑行按 位移-3，与 Stronghold 的当帧整段移动不同，见 DIF-0032）；网格的 `findPath`（寻路-2 的经过格子，[行, 列]，到不了为空）；单位援军的战术点（`findTacticalPoint`，照搬 Stronghold：攻击范围内可通行、可站立、没被占用的地面格，先取在敌人地面路线上的，再取最近的（切比雪夫距离，按朝向的侧向偏移小者优先），再取朝向坐标系里行列最小的）。候选目标的顺序（`sortEnemyTargets`）用引擎的索敌顺序（索敌-3）：Stronghold 的优先级中「防御最低」「重量最重」就是引擎的仇恨过滤器，其余在仇恨值顺序上再按该优先级排，最后把自己阻挡的放在最前（「空中优先」时空中的在更前）。这些模式里没有倒地的干员和敌方阵营的友方目标，相应查询为空。
- **范围的两种判定**：`enemiesInKeys` 按碰撞体积（体积-5：普通敌人半径 0.1 的圆盖住的格子，巨大敌人的矩形）。攻击档案带 `rangeTiles` 时（谬因：kit 的 `trait.rangeTiles`，或引擎特性数据里的同名标记，都写进单位的 `profile`）改走格子判定，与 `enemiesOnTiles` 相同（所占格，体积-1、体积-2）。`foesInColliderRadius(x, y, r)`：普通敌人的中心距离不超过 r + 0.1（常量-6），巨大敌人仍按其矩形是否在 r 内（体积-3）。`unitsInGrid` 以单位所在格为锚（体积-1 的五成双），`rangeTiles` 时用格子判定，否则用碰撞体积；友方始终按所占格。`onFieldBoard(r, c)` 为地图内且近战或远程可以站立的格子（推断 INF-0352），不算格上有没有干员（那是 `isReservedTile`）。
- **kit 可改的字段**：单位自己的攻击范围（攻击-1；设为空即恢复记录里的）；增益的剩余时间（整帧）、屏障量（不少于 0；用完的增益去掉还是留着，见下一条）和附带数据；技能的剩余时间（至少 1 帧）和充能数。单位距下次攻击的秒数（换成整帧，不少于 0，攻击-2）。单位的位置 `x`、`y`（直接放到那里，敌人从那里重新规划正在走的路，路线-5）。增益的层数（状态-2）；运行中的弹药技能剩余的弹药（技能-4）。单位的生命（直接设定，伤害-9）；敌人被谁阻挡（`blockedBy`：设为一个单位即立即被它阻挡，设为空即解除，阻挡-1、阻挡-3）。元素损伤与爆发的事件（`elementHit`、`elementBurst`，钩子-3）给 kit 的元素用 Stronghold 的名字（`neural`、`erosion`、`burn`、`apoptosis`）。

网格的路线点（`waypoints`）原来是缺口（兼容-2：调用时报错，这一次跳过并记下），现在按引擎的寻路给出（`tiles.js`）；kit 看到的单位另有行动方式（`motion`，`unit.js`）：

- **路线点**：`waypoints(起点行, 起点列, 终点行, 终点列, 选项)` 是敌人的地面路线从起点格到终点格的点，每点 [行, 列]：先是起点，再是终点格的地面流场（寻路-1）平滑后的指向（寻路-2）从起点起依次指到的格，最后是终点。不给选项时，相邻两点用 Bresenham 直线连起来就是 `findPath` 的经过格子。起点就是终点时只有起点。终点格本身不必可通行：流场从它出发。在地图外、行或列不是整数、起点到不了终点时为空。到不了是指起点格地面单位不能走，或者起点与终点被地面单位不能走的格、对地面单位封闭的格边（地图-2）隔开。格上的单位不算。
- **选项**：`allowDiagonal` 不给时为真，同 Stronghold；给了假值时只认同一行或同一列的视线（寻路-2 的不允许斜走的路线）。它只改点，不改能不能到。内容放置的障碍物还没有，`ignoreObstacles` 不改结果，同 `findPath`。
- **与 Stronghold 的不同**：点是引擎流场的指向，没有 Stronghold 自己加的「可阻挡地面优先」——等长的路线里，它改走经过近战干员不能部署的地面格（地板、出怪点、保护目标等）更少、深水区不更多的一条。地穴（地图-4）的代价与视线、封闭的格边照引擎的规则，Stronghold 没有这两样。所以 kit 读到的点可能与 Stronghold 的不同；能不能到只在封闭的格边上不同。为推断 INF-1180。
- **所用的地图**：与 `findPath` 一样，是关卡自己的地块。引擎每帧所用的地图里，建成的液压式高台（守御-5）和阻挡路线的装置（寻路-1）所在格是类障碍物地块，这里没有。它们只加走出那一格的代价，不改哪些格走得到，所以能不能到不变；点可能与敌人此刻实际走的不同。为推断 INF-1181。
- **行动方式**（`motion`）：敌人（含中立单位）自己的行动方式，`FLY` 或 `WALK`。变成飞行（敌能-34）、变回地面（敌能-48）时跟着变；不看所在路线是不是空中路线，也不看它此刻是不是空中单位（浮空，状态-5；近地悬浮，敌能-48）。其他单位（干员、召唤物、装置）为 `GROUND`。同 Stronghold。
- **酒神的 kit**：固定提交里调用路线点的只有它，干员 kit 里读行动方式的也只有它。本能的召唤每 0.1 秒诱导它 x-1 范围里的敌人时，只取「可达」的：行动方式为 `FLY` 的，或者从所在格（kit 自己用 `Math.round` 取整）到召唤物所在格的路线点不为空的。PRTS 第二技能的备注说「可达目标」是按照寻路规则可直接抵达自身位置的目标；这句备注的问号提示说以召唤物所在地块为终点寻路、排除不可通行地块，路线点也是这样。提示另要求去掉敌人所在格之后到终点的距离＜1000，并按初始行动方式寻路，kit 不这样判定（不在本条）。对局里的本能的召唤没有 kit：Stronghold 由酒神的第三个天赋经 `_setupUnit` 把 kit 装给棋盘上还没部署的本能的召唤，兼容层没有这样的棋子，也没有这一步（不在本条），所以这条路径在对局里还走不到。

- 来源：设计决定（kit 的路线点用引擎的寻路，同 [ADR 0012](../adr/0012-stronghold-compatible-core.md)；行或列不是整数时为空：流场没有这样的格，Stronghold 对这样的起点给出无意义的点）；`waypoints` 的约定（沿流场的平滑路线点，起点与终点都算，起点就是终点时只有起点，到不了为 null，`allowDiagonal` 不给时为真，`ignoreObstacles`）与 `motion` 的取值（敌人 `WALK` 或 `FLY`，其他 `GROUND`；移动与寻路看它，不看是否空中单位）取自 Stronghold v0.3.1 的 `server/sim/grid.js`、`server/sim/units.js`（GPL-3.0-or-later），装置由 `server/sim/battle/summons.js` 作为友方造出、不带行动方式；调用路线点的是 `server/sim/content/kits/ops/op-phatm2.js` 第 137 行，固定提交的内容代码里唯一一处 `grid.waypoints`，那段 kit 由第三个天赋经 `battle._setupUnit` 装上；[PRTS「酒神」oldid=392146](https://prts.wiki/index.php?title=%E9%85%92%E7%A5%9E&oldid=392146) 第二技能「部署后诱导至多4名进入范围的可达敌人（优先精英或领袖）10秒」，备注「“可达目标”的判定为：按照寻路规则可直接抵达自身位置的目标」，这句备注的问号提示「以召唤物所在地块为终点进行寻路计算，排除不可通行地块，若有效寻路路径上排除掉敌方单位所在格后，敌方单位到终点的距离＜1000，即为判定通过」「在此寻路计算中，敌人的行动方式始终视为初始行动方式」；与 Stronghold 的不同为推断 INF-1180，所用的地图为推断 INF-1181；在 Stronghold 网格大小的随机地图上，只有道路与高台时路线点与固定提交的 `waypoints` 逐位相同，有地板时与它的官方指针相同；酒神的 kit 原样载入，本能的召唤诱导道路上的地面敌人与高台上的飞行敌人，不诱导高台上的和被封闭格边围住的地面敌人，格边打开就诱导（`packages/content/test/compat-waypoints.test.js`、`packages/content/test/compat-waypoints-kit.test.js`）

### 兼容-5 kit 的技能说明

kit 为技能写的说明（Stronghold 的 SkillSpec）接到引擎的技能运行上：

- **接法**：kit 说明过的每个技能，按技能 id 登记一个引擎的技能行为（技能-6，ADR 0055）。同一技能 id 的干员，有 kit 说明的按说明运行，没有的仍按引擎从数据生成的通用效果（技能-5）。登记了行为的技能不再有通用效果，所以 kit 的效果不会与之重复。
- **何时发动**：照引擎的规则（技能-3）——手动技能由玩家发动，自动技能按它自己的时机。kit 另加的触发范围、改动的触发规则都接受、不使用。
- **运行中**：说明的修饰器与标记在技能运行时作为一个增益加在干员身上（修饰键与标记名见 兼容-4）；开始、每帧、结束时调用说明的 `onStart`、`onTick`、`onEnd`——结束时先调用 `onEnd`（此时修饰器仍在；上下文带结束原因 `reason`，同 skillEnd 事件，技能-6），再去掉增益。技能的发动次数（`activations`）在调用 `onStart` 之前加 1，同 Stronghold。
- **类型与时长**：说明的类型为 `duration`、`toggle`（可关闭的持续技能）、`ammo`、`passive` 时，引擎按它计时（技能-6 的 `timing`），说明写了 `duration` 时持续这么多秒；`instant` 与 `charges`（可充能的 instant）在说明带自己的攻击时是下次攻击技能，否则沿用技能记录的类型。
- **攻击**：有说明的技能运行时，普通攻击从干员自己的攻击起算（倍率、段数、目标数都为 1，blackboard 的攻击键由说明自己读取），再加上说明的攻击覆盖（技能-5）：倍率（数字形式的 `dmgMul` 再乘上去，作用于整次攻击）、每次攻击的段数、目标数（`allInRange` 为范围内全部）、伤害类型或治疗、每段命中给的状态；函数形式的 `dmgMul(battle, unit, target)` 按目标给主目标的倍率，在防御之前乘到这次伤害上，并取代特性对这个目标的倍率（职业-8、职业-11），同 Stronghold 技能档案取代职业档案；`hitsFn` 返回 0 时这次攻击本身不对主目标造成伤害（命中在最前取消，其后的 `hit` 处理不再调用），命中回调照常以 0 伤害调用；这两项只作用于引擎攻击的命中，kit 自己造成的伤害不受影响；`attack.noAttack` 时技能期间不进行普通攻击（职业-13 的标记）。
- **命中与攻击之后**：引擎在一次攻击对每个目标的各段伤害结算后发 `attackHit`（引擎自己的事件，带合计伤害与类别：主目标、溅射、跳跃、余震）。技能运行时，或命中来自技能自己的攻击时（下次攻击技能的弹道在技能结束后才命中），每个受击者调用说明的 `attack.onEachHit`；主目标再调用 `attack.onHit` 与 `onHit`。一次攻击结算后（`attack` 事件）调用 `onAttack`，它把 `noAmmo` 设为是时这次攻击不耗弹药。
- **kit 自己的特性档案**（kit 的 `trait`，Stronghold 用它覆盖职业的档案，技能运行时说明的攻击再覆盖它）：每次攻击都按它——能否攻击（`canAttack`）与没有目标时储存能量（`storeEnergy`）经分支的特性行为（职业-6）；主目标的段数为 0 时取消这次命中，`dmgMul` 取代特性的倍率；`onEachHit` 对每个受击者、`afterHit` 在主目标之后、`afterAttack` 在一次攻击之后调用；技能说明的攻击给出伤害类型、没有声明治疗时，技能运行期间治疗干员的攻击改为攻击敌人（Buff 标记 `attackFoes`，职业-2；同 Stronghold 去掉档案的治疗）。kit 的特性替换了职业档案里引擎以特性数据表示的部分时，干员的特性数据随之改变：`afterHit` 取代投掷手的余震（Stronghold 唯一的职业 afterHit），`splashRadius` 取代溅射半径。Stronghold 没有职业规则、由 kit 自己实现特性的分支，引擎特性里相应的部分交给 kit：塑灵术师对自身召唤物阻挡的敌人的倍率（职业-14）取 1，由 kit 自己乘到命中上。kit 自己实现它那名干员的模组（Stronghold 的 kit 写明「the trait and both modules」），模组追加的特性也在内：带 kit 的干员不带引擎的模组追加特性（职业-17 的按目标倍率、职业-18 的条件增益、职业-20 的命中附带与光环、职业-21 的召唤物加倍）。部署、撤退与部署位的规则（职业-21 的首次部署费用、首次撤退的再部署时间、撤退返还、不占部署位的召唤物）仍是引擎的：Stronghold 没有部署费用（op-siege.js 写明 SOL-Y「首次部署时部署费用-4」在那里没有效果）。投出回旋投射物的那次攻击的档案（技能的攻击投出的用技能说明的，否则用 kit 的特性）有 `boomerangOnward` 时，投射物到达目标后由它接管（引擎的 `boomerangHit`，职业-12），同 Stronghold：上下文有 `home()`（干员仍是投出时那次部署）、`hit(目标)`（用这次攻击打另一个敌人）、`comeBack(x, y)`（从那里送回，只一次，返回回程的 `x`、`y` 与干员的位置 `tx`、`ty`）；它出错时投射物从命中处返回。它自己的 `install` 在天赋之前运行，并接管分支的部署效果（特性的增益与维持消耗不再由引擎给，同 Stronghold 的职业安装让位于它；攻击方式——子弹的倍率等——照常）。kit 的天赋在 kit 自己的 `install` 之前安装，同 Stronghold。
- **技能运行时的读写**：kit 读技能的有无、类型、是否运行、技力与充能、剩余时间与弹药、发动次数（整局累计）；可以直接设定技力，免费或照常发动、结束技能（原因同 Stronghold）。

- 来源：设计决定（手动技能由玩家发动：2026-10-12 的规划讨论，计划 E1d）；SkillSpec 的字段与调用时机取自 Stronghold 的 `docs/SIM.md` §7、`server/sim/skills.js`、`server/sim/ai.js`（GPL-3.0-or-later）；固定版本对照里推进之王的 kit 原样载入，三技能由玩家发动后攻击间隔 +1 秒、倍率 380%、命中时 40% 晕眩 1.5 秒，25 秒后结束；二技能在她攻击时自动发动，回 3 点费用、下次攻击倍率 340%（`packages/content/test/compat-skills.test.js`）

### 兼容-6 对局里的 kit

固定版本的 Stronghold kit 作为内置的脚本 mod 在对局中运行（ADR 0058）：

- **清单**：`packages/content/data/kits.json` 记下固定提交（与差分对照同一个）、72 个干员 kit 各自的文件，以及启用名单——在小关卡冒烟运行中不报错、并通过逐个 kit 的差分对照的才启用。通过的意思是：所有技能与 Stronghold 一致，或者只差已登记的差异——这样的 kit 在清单的 `differences` 里按技能记下预期的每一行对照差异和背后的差异编号（DIF，仍有效的），CI 要求实际差异与记下的逐行相同，多一行、少一行或变了都不通过。
- **逐个 kit 的差分对照**：同一个 kit、同一练度（Stronghold 自选的精英形态：精英二 60 级、潜能 6、信赖 0、技能 7 级、最后一个模组 3 级），在 Stronghold 自己的战斗测试工具里和在我们的引擎里，各对着身前一个不会移动的假敌人（生命 1e7、防御与法抗 0；Stronghold 的移速为 0，我们这边用一个不是状态的增益定住它——「束缚」是 kit 会查看的状态；它不站在自己的路线上）跑 40 秒。两边是同一块场地：我们的关卡逐格照搬 Stronghold 这一局的战场（高台、出怪点与保护目标、可部署与通行），干员与假敌人站在同样的格子上。技能按 Stronghold 的自动操作发动：手动技能在这一局里当作同一时机的自动技能——即将攻击时，或（每帧检查的规则、不攻击的干员）一就绪就发动，带 kit 触发范围的在范围里有敌人时就绪即发动、否则即将攻击时；开局即可发动，此后两次之间至少 3 秒；Stronghold 这一局一次没发动的技能我们这边也不发动。kit 的随机数在我们这边取 Stronghold 同一种子的随机数序列（这个场景里没有别的东西取用它，kit 的每次取数两边相同；对局里 kit 用对局自己的随机数，随机-1）。比较：部署 1 秒后的增益（不含技能的、不改任何东西的；分支特性的增益——我们引擎的 `trait`、Stronghold 的 `trait:<分支>`——只比修饰器，标记在 Stronghold 的攻击档案里；Stronghold 把解放者的「阻挡数×0」写成阻挡数 −99，按 ×0 比较）、每次命中扣掉的生命（不含元素损伤）和每次治疗的量（取各不相同的值：任一边的每个值在另一边都有相差 0.5%（至少 1）以内的值，算相同——Stronghold 的属性取整，随目标生命变化的伤害两边取到的值也多少不一）、技能发动次数（相差不超过 1）、施加的状态（种类与秒数）、我们这边记下的 kit 错误。启用名单里的 kit 都必须全部一致（记下预期差异的除外，按上一条），CI 每次检查。
- **载入**：按对局里的干员，载入其中已启用的 kit，按角色 id 的顺序逐个载入（兼容-1 的载入网格）；载入不了的记下，那名干员按引擎自己的实现。Node 里从固定提交的目录载入（兼容-2 的加载钩子）；浏览器里从平台提供的、已按映射表改写导入的副本载入，浏览器端不改写。
- **对局内容**：有 kit 的干员用 kit：它的记录去掉天赋部分（天赋由 kit 施加；傀儡师替身的不攻击与光环也去掉，替身的范围保留，职业-16），它的队伍天赋不由引擎再给；kit 的每局挂接与技能行为（兼容-4、兼容-5）加进内容。内容记下固定提交与所用的 kit（按角色 id 排序），这一项计入内容哈希（同步-10）：两端载入的 kit 不同，就不开局。

### 兼容-7 kit 的状态生效、敌人出手与麻痹事件

钩子-5 的三个事件给 kit 的上下文同 Stronghold：

- **`statusApplied`**：`source`、`target` 是 kit 看到的单位（兼容-4）；`status` 用 Stronghold 的名字（`bind`、`resist`、`tremble`；敌人施加的寒冷、冻结也是 `cold`、`freeze`）；`duration` 为秒（剩余帧数 × 1/30，无期限为 `Infinity`）——抵抗与重量在引擎里按衰减率缩短状态（状态-3、状态-5），不在这个数里，Stronghold 的是施加时乘过的（抵抗见 DIF-0006）；`value` 为数值；`entered` 同引擎。免疫的目标也发（钩子-5），Stronghold 免疫时不施加，也就不发（DIF-0012）。兼容层代用的状态（`defDown`，兼容-4）生效后同样发，`entered` 为施加前目标没有这个键的增益。
- **`enemyAttackStart`**：`enemy` 和 `targets` 是 kit 看到的单位。kit 在这里让敌人晕眩、倒下（或 钩子-5 列出的别的情形）时，这次攻击取消。
- **`palsyTrigger`**：`enemy`；`buff` 是 kit 看到的麻痹增益（层数、剩余时间……，兼容-4）；`keep` 直接读写引擎的上下文，设为是时这一层不消耗。
- 固定版本（v0.3.1）的 72 个干员 kit 里，酒神的「堕梦」用 `enemyAttackStart`，真言的「噤声限域」用 `palsyTrigger` 和 `keep`；`statusApplied` 干员 kit 不用：Stronghold 里用它的是棋子 kit、驻防的代码（盟约）和把它转给敌人能力的 `content/enemies.js`，兼容层都不载入。Stronghold 让内容把已有的状态当作新进入的选项（`reenter`，棋子 kit 缇缇）不提供。

- 来源：设计决定，见 [ADR 0057](../adr/0057-hook-bus-and-timers.md)（事件名沿用 Stronghold 的，兼容层把上下文转成它的形状）；上下文的字段与含义取自 Stronghold v0.3.1 的 `docs/SIM.md` §5、`server/sim/battle/status.js`、`server/sim/ai.js`（GPL-3.0-or-later）；固定版本里真言、酒神的 kit 原样载入，在小关卡中：麻痹打断敌人的攻击时真言的「噤声限域」按她当前的攻击力造成元素伤害，几率取 1 时不消耗那一层、取 0 时消耗；敌人的攻击落下时，酒神攻击范围内的敌人受到「堕梦」的神经损伤，它引起的爆发打断这次攻击（`packages/content/test/compat-morehooks.test.js`）
