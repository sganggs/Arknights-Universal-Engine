# Stronghold 兼容层

兼容层只在 `packages/content/src/compat/` 里（ADR 0045）。kit 的源码不改，只由导入路径映射表把它们的导入指向我们的模块（ADR 0010）。

### 兼容-1 网格尺寸

Stronghold 的常量模块把网格的列数 `COLS`、行数 `ROWS` 给成固定的数；我们的地图大小每关不同。

- 映射表把 kit 对常量模块的导入指向兼容层，其中 `COLS`、`ROWS` 是活的绑定：运行一场战斗的内容代码时（`withGrid`），它们是这一关的宽和高；之后恢复成之前的值，内容代码抛出异常或两场战斗的代码嵌套时也一样。
- kit 在函数里读 `COLS`、`ROWS`（编码、解码格子键，边界检查，遍历网格），每次调用读到的是当时这一关的尺寸。
- 在模块加载时就读的，值固定在加载那一刻。所以兼容层加载 kit 时，`COLS`、`ROWS` 都是 64（`LOAD_GRID`），大于任何关卡（数据里最大 50 × 44）：按地图大小生成的「整行」「整图」列表覆盖每一关，地图外的格子在算攻击范围时去掉（索敌-1）。固定提交的 Stronghold 内容代码里只有一处这样取值：`kits/ops/chess_char_4_20-fartth.js` 第 11 行的 `LINE`（远牙三技能的无限直线范围）。

- 来源：设计决定，见 [ADR 0010](../adr/0010-import-mapping-table.md)（只改写导入路径，不改 kit 源码）、[ADR 0012](../adr/0012-stronghold-compatible-core.md)、[ADR 0045](../adr/0045-unit-field-ownership-compat-isolation.md)；用法统计：ArknightsGameData 的 3943 个关卡中地图最宽 50、最高 44；固定的 Stronghold 提交中 83 个文件引用 `COLS` / `ROWS`（内容代码 66 个），按语法树分析，内容代码在加载时读取的只有上面一处（`packages/content/test/compat-grid.test.js`，ADR 0056）

### 兼容-2 映射表与 kit 的载入

- **映射表**：Stronghold 的 kit 所及的每个引擎模块（按它在 Stronghold 仓库里的路径）对应兼容层里的一个替身模块：`server/sim/` 下的 constants、detmath、dir、targeting、body、damage、buffs、ai、professions、simdata，以及 `server/data.js`、`shared/constants.js`、`shared/potential.js`，共 13 个。内容文件（`server/sim/content/` 下：kit、它们共用的帮手、召唤物与道具模块）原样载入，只把它们对引擎模块的导入换成替身。映射表里没有的引擎模块被导入时报错，kit 新增的依赖立刻显出来。
- **加载钩子**：Node 的加载钩子由映射表生成，给出 Stronghold 仓库的根和兼容层的目录，就按表改写 Stronghold 文件里的相对导入。
- **替身**：
  - 纯函数直接给出：方向（按名字的四个朝向，朝右写的偏移每步转四分之一：右 (dr, dc)、上 (dc, −dr)、左 (−dr, −dc)、下 (−dc, dr)；第 0 行在最下，上为行号增大，与 方向-1 一致；不出现 −0）用 Stronghold 的写法移植；确定性数学用引擎自己的（与它逐位一致，数值-2…数值-5）；常量中 `COLS`、`ROWS` 按 兼容-1，`TICK` 为一帧（时间-1），其余先取 Stronghold v0.2.4 的值，用到它们的 kit 与对照比较时逐个核对。增益的合计（buffs 的 `aggregateMods`：同名修饰加算 × 层数，`…Mul` 连乘至层数次方，闪避按独立概率合并）与攻击档案（ai 的 `effectiveProfile`，兼容-4）也用 Stronghold 的写法移植。持续效果的伤害说明（damage 的 `periodicDamage`）为记在来源名下的无来源真实伤害（伤害-7），不可闪避，带 `dot`、`periodic` 标签。记录在某一潜能下的样子（potential 的 `atPotential`）就是记录本身：我们的记录本来就按所选潜能造出（兼容-3），没有 Stronghold 记录里的潜能注记。
  - 还没有提供的名字以「缺口」存在：kit 载入时它在，被调用时报错并写明模块和名字，不会悄悄做别的事。
- 固定版本的对照（Stronghold v0.2.4）里 72 个干员 kit（`kits/ops/op-*.js`）都原样载入；129 个棋子 kit（`kits/ops/chess_*.js`，卫戍协议的棋子，Stronghold Protocol 的 aue 分支用）也都能载入。

- 来源：设计决定，见 [ADR 0010](../adr/0010-import-mapping-table.md)、[ADR 0012](../adr/0012-stronghold-compatible-core.md)；方向的写法取自 Stronghold 的 `server/sim/dir.js`（GPL-3.0-or-later）；kit 的导入闭包按语法统计：72 个 kit 和 9 个共用内容文件，引擎模块 13 个、61 个名字；棋子 kit 另用到 6 个名字（常量 `CHAIN_RADIUS`、`ELEMENT_GAUGE_MAX`，取固定提交的值；`powi` 用引擎自己的；`attackCountdown`、`applyRedirectCut`、`redirectShare` 先作缺口）

### 兼容-3 kit 的输入：记录与定义

kit 的工厂收到 `(bb, chess, def)`：所选技能的 blackboard、这名干员的记录、规范化后的定义。兼容层用引擎自己的练度数据（干员-1…干员-7）造出它们，形状同 Stronghold 的「自选」记录，但练度任意：

- **身份**：干员 id；所在的「槽位」写作 `aue_<干员 id>`。
- **属性**：这一练度下干员自己的属性（精英化与等级、信赖、潜能、模组的加值），不含天赋的效果——天赋由 kit 自己施加。部署费用、阻挡数、攻击间隔、再部署时间等照搬；技力回复为每秒 1。
- **范围**：这一精英阶段的攻击范围；**特性**：已解锁的最后一个特性 blackboard，模组改写特性时用模组的值覆盖（干员-7）；模组只作展示的特性部件（`DISPLAY`，追加一行说明）带的 blackboard 也并入，同 Stronghold 的记录（这一行的效果游戏里由隐藏天赋给出，kit 从特性读它）。
- **天赋**：每个天赋已解锁的最后一项；模组改写天赋时，模组的值覆盖、天赋原有的其余键保留，改写不属于任何天赋的（序号 −1，如攻击范围）另加一条。
- **技能**：这一精英阶段已解锁的每个技能在所选技能等级上的数据；所选的那个作为 `skill`。
- **技能范围**：kit 技能说明的 `targeting.rangeGrid`（朝右写的 [行, 列] 偏移）是技能运行时的攻击范围（技能-8），按这时的内容读——kit 在开始时原地重算也照用（司霆惊蛰 S2 的低地洪水填充）；没有时用记录的范围。
- **说明文字**：技能、天赋、模组的天赋改动和召唤物的说明同 Stronghold 的记录：占位符（`{key}`、`{-key}`、`{key:0%}`）按 blackboard 代入，`desc` 去掉官方的富文本标记，`descRaw` 保留标记（kit 会从说明里读数，如望的「最多拥有8（+1）枚」）。
- **模组**：所选模组及等级；没有时为未装备。另列出这一练度下已解锁的每个模组，各在所选模组等级上：平加的属性、特性（不改写特性时为空）、天赋改动——都按模组自己写的值（一个天赋部分里已解锁的最后一项，即潜能对应的那一档），不与天赋合并。
- **不带模组的记录**：属性、特性、天赋各再给一份不带模组的（`statsBase`、`traitBase`、`talentsBase`）。kit 用它们分开天赋本身与模组的追加：推进之王的「万兽之王」在模组「糖果盒」3 级下，给全体先锋的取天赋本身的 +10%，自身额外的 +8% 取模组的改动（合并后的天赋里两者同名，只剩 8%）。
- **定义**：记录按 Stronghold 的规则规范化，再带上所选技能、模组与潜能。
- **召唤物原始记录**：战斗对象的 `data.rawToken(id)` 给出召唤物在其召唤者练度下的记录（这局里第一个持有它的棋子的），场上上限另放在顶层，同 Stronghold 的 tokens.json；没有棋子持有它时为空。

- 来源：设计决定，见 [ADR 0016](../adr/0016-arbitrary-operator-levels.md)（任意练度在数据层计算）；记录的形状与规范化、天赋的合并规则取自 Stronghold 的 `server/sim/simdata.js`、`shared/loadoutRecord.js`（GPL-3.0-or-later）；模组选项的字段（`modules[]`、`…Base`）同 Stronghold 的数据说明 `docs/DATA.md` §2.2；72 个 kit 在每个技能（精英二满级、最后一个模组 3 级）与精英零、精英一 1 级下都能由这些输入造出 kit


### 兼容-4 战斗里的 kit

kit 在战斗里看到的是 Stronghold 的战斗对象；兼容层用引擎的世界给出它（`packages/content/src/compat/battle.js`、`unit.js`、`skill.js`、`kits.js`）：

- **挂接**：内容的开局挂接（钩子-4）造出这局的战斗对象；牌组里每个有 kit 的干员得到一个「棋子」，整局一个，同 Stronghold 的棋盘棋子。棋子的 id 也整局不变：开局前从引擎预留（钩子-4 的 `reserveIds`，按座位、牌组顺序），部署前、两次部署之间都一样；按 id 找单位时它找得到棋子，其他单位用引擎的 id。开局前每个棋子的 kit 装一次：kit 自己的安装和各天赋的安装。
- **部署**：干员每次入场时（钩子-3 的 `enter`：它的特性、天赋、被动技能生效之前，同 Stronghold 先装好 kit 再启动被动技能），先于任何 kit 对这次部署的处理，把它的棋子绑定到引擎的单位上，再把它的持久增益重新给上。撤退或阵亡后棋子解绑，kit 装下的钩子与计时器留着，看得到之后的每次部署。
- **单位**：kit 看到的单位有 Stronghold 的字段与读取方式：位置、格子、朝向、生命、当前属性、阻挡的敌人、增益，都从引擎的状态现读。属性的标记另以 Stronghold 的名字给出（`invulnerable`、`bind`、`noHeal`），元素爆发中另有 `burstLock`。kit 自己存的状态（`mem`、`trait`）在兼容层，不在引擎的状态里（ADR 0057）。没有 kit 的干员和敌人也以同样的样子给出。kit 选友方时（光环、治疗、给增益）不选孤立的单位，自己除外。另有：部署时刻（`deployedAt`，战斗秒数）、在地面（`ground`：我方在地面格、敌方不在空中）、是不是领袖（`isBoss`）、距下次攻击的秒数（`atkCd`）；攻击档案（`effectiveProfile`）为它特性的档案，技能运行且说明有攻击或索敌覆盖时叠上这些覆盖（兼容-5）。战斗对象给出战斗秒数 `time`（这一帧开始时，帧 × 1/30，同一帧的处理里都相同）和是否已经结束（`finished`，结束-1）。朝向的一步（`fwd`，方向-1：向上为行 + 1）；额外攻击格（`extraRangeKeys`，战斗对象的 `setExtraRange` 设置，攻击-1）。
- **钩子与计时**：用引擎的钩子与计时器（钩子-1…钩子-3）。传给 kit 的上下文换成 Stronghold 的形状：单位换成上面的样子，`tick` 的帧数换成秒数 `dt`；kit 给的秒数换成整帧（时间-2：`after(1)` 在 30 帧后，`every(0.5)` 每 15 帧）。
- **出错**：kit 的工厂、安装、钩子处理、计时器抛出异常时，这一次跳过并记下（哪一步、哪名干员、消息），战斗照常进行——Stronghold 也这样隔离内容的错误。
- **场上的查询与动作**（`field.js`）：格子上、半径内可选中的敌人（索敌-2：在场有血、未消失，不是无法选中、隐匿生效（被阻挡时、恢复窗口中不算）、离场的；睡眠的只有能打睡眠的可选；飞行的只有能对空且不限地面的可选），某格上的友方单位，单位阻挡的敌人；造成伤害（伤害-7；干员造成的记击杀，职业-5；元素损伤记到目标的元素上，元素-2）、治疗（伤害-11）、生命流失（伤害-10，带 Stronghold 的标签）、撤退（撤退-1）、移动（`moveRedeploy`：部署-9 的保留方式，生命、Buff 和技能都保留，与 Stronghold 相同，见 DIF-0034；Stronghold 拒绝的——离场的、目标格有别的友方——和引擎会改为撤退的都拒绝，不做任何事；`clearSp` 时先清空技力，运行中的持续技能除外；算一次新的部署）。伤害链、攻击、技能、状态的事件（钩子-3）给 kit 的上下文同 Stronghold：可改的数（`hpDamage` 与 `heal` 的量、`fatal` 的阻止、`beforeStatus` 的时长（秒）、数值与取消）直接改在引擎的上下文上；`beforeAttack` 的目标列表 kit 可以整个换掉，也可以原地增删，每个处理函数之后写回引擎。单位另有空中、能否行动、重量、阻挡它的单位、当前攻击范围的格子与职业的选择规则（能否对空）、增益列表等读取方式；攻击范围内可选的友方；格子上需要治疗的友方（生命比例低的在前）；格子是否已被占用；敌人剩余的路径距离（索敌-6）；放开单位阻挡的敌人（阻挡-3）；敌人地面路线经过的格子（`groundPathTiles`：关卡波次用到的非飞行路线——都没有指明时为全部非飞行路线——从起点经 MOVE、APPEAR_AT_POS 检查点到终点，各段为 寻路-2 的经过格子）；一次攻击会取的目标（ai 的 `acquireTargets`，照搬 Stronghold：治疗取范围内受伤的友方，生命比例低的在前；否则取范围内可选的敌人与自己阻挡的，`allInRange` 全取，否则按优先级取目标数个）；放开一个敌人的阻挡（`_unblock`，阻挡-3）；立即攻击（`forceAttack`：攻击-5，给定目标或它自己会取的，`noAmmo` 时不耗弹药）；kit 自己的投射物（`addProjectile`，照搬 Stronghold：追踪单位或飞向定点、按速度每帧移动，到达时调用 `onHit`；目标离场或重新部署时作废，`hitDead` 时落在最后已知的位置；最长 10 秒。它们是 kit 的状态，每帧在 `tick` 处理函数之前推进，暂不绘制）；半径内的友方（`alliesInRadius`，按中心，可限一名玩家）；推开（`push`：位移-2，`dir` 给方向，`fixed`、`fixedAngle` 免去修正，`inward` 朝推动者，`effect` 为特效类；之后的失衡滑行按 位移-3，与 Stronghold 的当帧整段移动不同，见 DIF-0032）；网格的 `findPath`（寻路-2 的经过格子，[行, 列]，到不了为空）；单位援军的战术点（`findTacticalPoint`，照搬 Stronghold：攻击范围内可通行、可站立、没被占用的地面格，先取在敌人地面路线上的，再取最近的（切比雪夫距离，按朝向的侧向偏移小者优先），再取朝向坐标系里行列最小的）。候选目标的顺序（`sortEnemyTargets`）用引擎的索敌顺序（索敌-3）：Stronghold 的优先级中「防御最低」「重量最重」就是引擎的仇恨过滤器，其余在仇恨值顺序上再按该优先级排，最后把自己阻挡的放在最前（「空中优先」时空中的在更前）。这些模式里没有倒地的干员和敌方阵营的友方目标，相应查询为空。
- **kit 可改的字段**：单位自己的攻击范围（攻击-1；设为空即恢复记录里的）；增益的剩余时间（整帧）、护盾量（不少于 0，只剩空护盾的增益随之去掉）和附带数据；技能的剩余时间（至少 1 帧）和充能数。单位距下次攻击的秒数（换成整帧，不少于 0，攻击-2）。单位的位置 `x`、`y`（直接放到那里，敌人从那里重新规划正在走的路，路线-5）。增益的层数（状态-2）；运行中的弹药技能剩余的弹药（技能-4）。单位的生命（直接设定，伤害-9）；敌人被谁阻挡（`blockedBy`：设为一个单位即立即被它阻挡，设为空即解除，阻挡-1、阻挡-3）。元素损伤与爆发的事件（`elementHit`、`elementBurst`，钩子-3）给 kit 的元素用 Stronghold 的名字（`neural`、`erosion`、`burn`、`apoptosis`）。
- **网格**：整张地图是战斗的范围；每格按 Stronghold 的说法给出高低、可部署的类型、通行方式（地面、只许飞行、不可通行）和起点、终点格；能否放置单位按 Stronghold 的规则。内容放置的障碍物和寻路还没有。
- **费用、增益、状态、随机数**：加费用即 费用-1 的获得费用，到上限为止；玩家（`getPlayer`）给出它现有的费用（`dp`）和它的单位；行商的扣费前有 `merchantPay` 事件（职业-10、钩子-3），kit 可改这次的费用或取消。增益的刷新规则对应引擎的同名规则（状态-2）：`extend`、`stack`、`independent` 同名；`keep` 已有同名时不加；默认替换。持久的增益在单位下场后留着，下次部署再给；不在场的单位只记下持久的。状态用引擎的状态表（状态-5），Stronghold 的名字不同的换成引擎的（束缚、抵抗、战栗）；Stronghold 状态表里官方异常效果没有对应的，由兼容层以同键的增益代替（`defDown`：防御力最终乘算 ×(1 − v)，没给强度时 0.3，同名取最高），施加前同样发 `beforeStatus`（处理函数可取消、改时长与强度）；其余引擎还没有的报缺口；增益看到的状态名用 Stronghold 的；「效果取最高」用引擎的同名规则（状态-2）；kit 换掉增益的修饰器时生命按比例保持（属性-4）。带回调的增益：`onTick` 每 `interval` 秒一次（秒数换成整帧，至少 1 帧；没有间隔为每帧，`dt` 为间隔或一帧的秒数），`onExpire` 在时间用完时，`onRemove` 在 kit 移除它时——在引擎里它仍是纯数据的增益，触发间隔即 `interval`（固定触发，状态-4），行为键指向兼容层的一条行为（状态-1），回调按增益存在兼容层，调用时上下文同 Stronghold（`battle`、`unit`、`buff`、`dt`）。元素爆发的增益用 Stronghold 的名字（`burnBurst`、`neuralBurst`、`apoptosisBurst`、`erosionBurst`，元素-3）查找、移除和显示。随机数用这局的随机流（随机-1）。演出效果暂不绘制。随机数的方法按 Stronghold 的签名：`int(n)` 取 0…n − 1，`range(a, b)`，`chance(p)`，`pick(list)`，`shuffle(list)`，`weighted(list, 权重函数)` 返回选中的元素（都没有权重时为空）。
- **技能说明的命中效果**：带 kit 规格的技能，攻击不带引擎从技能说明读出的限时减益、自身回复、元素损伤和推拉（技能-9），这些由 kit 自己实现。
- **技能与技力**：kit 读引擎的技能状态：有没有技能、技能的类型（kit 写明的优先，否则 技能-1 的分类）、是否在运行。kit 给技力按 Stronghold 的规则：持续型技能（持续、弹药、开关）运行中或阻回时不给；kit 标为无视阻回的（Stronghold 的 `'init'` 与写明的例外）照给（技能-2）；都到技力条上限为止。kit 写的技能说明本身还不运行，技能仍按引擎自己的（技能-1…技能-9）。
- **一次攻击的档案**：`beforeAttack` 的上下文带这次攻击的档案（`profile`，Stronghold 的 effectiveProfile 的副本，只属于这次攻击）。kit 改了它的 `atkScale`，这次攻击的倍率按改后与原来之比改变（引擎的 `scale`，钩子-3）；改了它的 `afterHit`，这次攻击（含它的投射物）的命中调用改后的，别的攻击照旧（引擎的 `mark`）。

- 来源：设计决定，见 [ADR 0012](../adr/0012-stronghold-compatible-core.md)、[ADR 0057](../adr/0057-hook-bus-and-timers.md)；增益的刷新规则、技力的锁、内容错误的隔离、棋子整局一份取自 Stronghold 的 `server/sim/Battle.js`、`buffs.js`、`skills.js`（GPL-3.0-or-later）；固定版本对照里推进之王的 kit 原样载入，在小关卡中光环、自身加成、阻挡时的特性、「粉碎」的技力与二次部署按其说明生效，同一局跑两次每帧状态相同（`packages/content/test/compat-battle.test.js`）

### 兼容-5 kit 的技能说明

kit 为技能写的说明（Stronghold 的 SkillSpec）接到引擎的技能运行上：

- **接法**：kit 说明过的每个技能，按技能 id 登记一个引擎的技能行为（技能-6，ADR 0055）。同一技能 id 的干员，有 kit 说明的按说明运行，没有的仍按引擎从数据生成的通用效果（技能-5）。登记了行为的技能不再有通用效果，所以 kit 的效果不会与之重复。
- **何时发动**：照引擎的规则（技能-3）——手动技能由玩家发动，自动技能按它自己的时机。kit 另加的触发范围、改动的触发规则都接受、不使用。
- **运行中**：说明的修饰器与标记在技能运行时作为一个增益加在干员身上（修饰键与标记名见 兼容-4）；开始、每帧、结束时调用说明的 `onStart`、`onTick`、`onEnd`——结束时先调用 `onEnd`（此时修饰器仍在；上下文带结束原因 `reason`，同 skillEnd 事件，技能-6），再去掉增益。技能的发动次数（`activations`）在调用 `onStart` 之前加 1，同 Stronghold。
- **类型与时长**：说明的类型为 `duration`、`toggle`（可关闭的持续技能）、`ammo`、`passive` 时，引擎按它计时（技能-6 的 `timing`），说明写了 `duration` 时持续这么多秒；`instant` 与 `charges`（可充能的 instant）在说明带自己的攻击时是下次攻击技能，否则沿用技能记录的类型。
- **攻击**：有说明的技能运行时，普通攻击从干员自己的攻击起算（倍率、段数、目标数都为 1，blackboard 的攻击键由说明自己读取），再加上说明的攻击覆盖（技能-5）：倍率（数字形式的 `dmgMul` 再乘上去，作用于整次攻击）、每次攻击的段数、目标数（`allInRange` 为范围内全部）、伤害类型或治疗、每段命中给的状态；函数形式的 `dmgMul(battle, unit, target)` 按目标给主目标的倍率，在防御之前乘到这次伤害上，并取代特性对这个目标的倍率（职业-8、职业-11），同 Stronghold 技能档案取代职业档案；`hitsFn` 返回 0 时这次攻击本身不对主目标造成伤害（命中在最前取消，其后的 `hit` 处理不再调用），命中回调照常以 0 伤害调用；这两项只作用于引擎攻击的命中，kit 自己造成的伤害不受影响；`attack.noAttack` 时技能期间不进行普通攻击（职业-13 的标记）。
- **命中与攻击之后**：引擎在一次攻击对每个目标的各段伤害结算后发 `attackHit`（引擎自己的事件，带合计伤害与类别：主目标、溅射、跳跃、余震）。技能运行时，或命中来自技能自己的攻击时（下次攻击技能的弹道在技能结束后才命中），每个受击者调用说明的 `attack.onEachHit`；主目标再调用 `attack.onHit` 与 `onHit`。一次攻击结算后（`attack` 事件）调用 `onAttack`，它把 `noAmmo` 设为是时这次攻击不耗弹药。
- **kit 自己的特性档案**（kit 的 `trait`，Stronghold 用它覆盖职业的档案，技能运行时说明的攻击再覆盖它）：每次攻击都按它——能否攻击（`canAttack`）与没有目标时储存能量（`storeEnergy`）经分支的特性行为（职业-6）；主目标的段数为 0 时取消这次命中，`dmgMul` 取代特性的倍率；`onEachHit` 对每个受击者、`afterHit` 在主目标之后、`afterAttack` 在一次攻击之后调用；技能说明的攻击给出伤害类型、没有声明治疗时，技能运行期间治疗干员的攻击改为攻击敌人（Buff 标记 `attackFoes`，职业-2；同 Stronghold 去掉档案的治疗）。kit 的特性替换了职业档案里引擎以特性数据表示的部分时，干员的特性数据随之改变：`afterHit` 取代投掷手的余震（Stronghold 唯一的职业 afterHit），`splashRadius` 取代溅射半径。Stronghold 没有职业规则、由 kit 自己实现特性的分支，引擎特性里相应的部分交给 kit：塑灵术师对自身召唤物阻挡的敌人的倍率（职业-14）取 1，由 kit 自己乘到命中上。kit 自己实现它那名干员的模组（Stronghold 的 kit 写明「the trait and both modules」），模组追加的特性也在内：带 kit 的干员不带引擎的模组追加特性（职业-17 的按目标倍率、职业-18 的条件增益、职业-20 的命中附带与光环、职业-21 的召唤物加倍）。部署、撤退与部署位的规则（职业-21 的首次部署费用、首次撤退的再部署时间、撤退返还、不占部署位的召唤物）仍是引擎的：Stronghold 没有部署费用（op-siege.js 写明 SOL-Y「首次部署时部署费用-4」在那里没有效果）。投出回旋投射物的那次攻击的档案（技能的攻击投出的用技能说明的，否则用 kit 的特性）有 `boomerangOnward` 时，投射物到达目标后由它接管（引擎的 `boomerangHit`，职业-12），同 Stronghold：上下文有 `home()`（干员仍是投出时那次部署）、`hit(目标)`（用这次攻击打另一个敌人）、`comeBack(x, y)`（从那里送回，只一次，返回回程的 `x`、`y` 与干员的位置 `tx`、`ty`）；它出错时投射物从命中处返回。它自己的 `install` 在天赋之前运行，并接管分支的部署效果（特性的增益与维持消耗不再由引擎给，同 Stronghold 的职业安装让位于它；攻击方式——子弹的倍率等——照常）。kit 的天赋在 kit 自己的 `install` 之前安装，同 Stronghold。
- **技能运行时的读写**：kit 读技能的有无、类型、是否运行、技力与充能、剩余时间与弹药、发动次数（整局累计）；可以直接设定技力，免费或照常发动、结束技能（原因同 Stronghold）。

- 来源：设计决定（手动技能由玩家发动：2026-10-12 的规划讨论，计划 E1d）；SkillSpec 的字段与调用时机取自 Stronghold 的 `docs/SIM.md` §7、`server/sim/skills.js`、`server/sim/ai.js`（GPL-3.0-or-later）；固定版本对照里推进之王的 kit 原样载入，三技能由玩家发动后攻击间隔 +1 秒、倍率 380%、命中时 40% 晕眩 1.5 秒，25 秒后结束；二技能在她攻击时自动发动，回 3 点费用、下次攻击倍率 340%（`packages/content/test/compat-skills.test.js`）

### 兼容-6 对局里的 kit

固定版本的 Stronghold kit 作为内置的脚本 mod 在对局中运行（ADR 0058）：

- **清单**：`packages/content/data/kits.json` 记下固定提交（与差分对照同一个）、72 个干员 kit 各自的文件，以及启用名单——在小关卡冒烟运行中不报错、并通过逐个 kit 的差分对照的才启用。通过的意思是：所有技能与 Stronghold 一致，或者只差已登记的差异——这样的 kit 在清单的 `differences` 里按技能记下预期的每一行对照差异和背后的差异编号（DIF，仍有效的），CI 要求实际差异与记下的逐行相同，多一行、少一行或变了都不通过。
- **逐个 kit 的差分对照**：同一个 kit、同一练度（Stronghold 自选的精英形态：精英二 60 级、潜能 6、信赖 0、技能 7 级、最后一个模组 3 级），在 Stronghold 自己的战斗测试工具里和在我们的引擎里，各对着身前一个不会移动的假敌人（生命 1e7、防御与法抗 0；Stronghold 的移速为 0，我们这边用一个不是状态的增益定住它——「束缚」是 kit 会查看的状态；它不站在自己的路线上）跑 40 秒。两边是同一块场地：我们的关卡逐格照搬 Stronghold 这一局的战场（高台、出怪点与保护目标、可部署与通行），干员与假敌人站在同样的格子上。技能按 Stronghold 的自动操作发动：手动技能在这一局里当作同一时机的自动技能——即将攻击时，或（每帧检查的规则、不攻击的干员）一就绪就发动，带 kit 触发范围的在范围里有敌人时就绪即发动、否则即将攻击时；开局即可发动，此后两次之间至少 3 秒；Stronghold 这一局一次没发动的技能我们这边也不发动。kit 的随机数在我们这边取 Stronghold 同一种子的随机数序列（这个场景里没有别的东西取用它，kit 的每次取数两边相同；对局里 kit 用对局自己的随机数，随机-1）。比较：部署 1 秒后的增益（不含技能的、不改任何东西的；分支特性的增益——我们引擎的 `trait`、Stronghold 的 `trait:<分支>`——只比修饰器，标记在 Stronghold 的攻击档案里；Stronghold 把解放者的「阻挡数×0」写成阻挡数 −99，按 ×0 比较）、每次命中扣掉的生命（不含元素损伤）和每次治疗的量（取各不相同的值：任一边的每个值在另一边都有相差 0.5%（至少 1）以内的值，算相同——Stronghold 的属性取整，随目标生命变化的伤害两边取到的值也多少不一）、技能发动次数（相差不超过 1）、施加的状态（种类与秒数）、我们这边记下的 kit 错误。启用名单里的 kit 都必须全部一致（记下预期差异的除外，按上一条），CI 每次检查。
- **载入**：按对局里的干员，载入其中已启用的 kit，按角色 id 的顺序逐个载入（兼容-1 的载入网格）；载入不了的记下，那名干员按引擎自己的实现。Node 里从固定提交的目录载入（兼容-2 的加载钩子）；浏览器里从平台提供的、已按映射表改写导入的副本载入，浏览器端不改写。
- **对局内容**：有 kit 的干员用 kit：它的记录去掉天赋部分（天赋由 kit 施加；傀儡师替身的不攻击与光环也去掉，替身的范围保留，职业-16），它的队伍天赋不由引擎再给；kit 的每局挂接与技能行为（兼容-4、兼容-5）加进内容。内容记下固定提交与所用的 kit（按角色 id 排序），这一项计入内容哈希（同步-10）：两端载入的 kit 不同，就不开局。
