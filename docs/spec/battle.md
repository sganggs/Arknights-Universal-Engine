# 战斗循环与同步

### 帧-1 一帧内的顺序

每一帧按固定顺序执行：

1. 这一帧的指令，按服务器封口时的顺序；然后到期的定时器（钩子-2）；第 0 帧还发出战斗开始事件（钩子-3）；
2. 费用增长；
3. 按座位顺序：复活倒计时（合作-4），然后费用请求的冷却和等待（合作-5）；
4. 波次：这一帧到期的波次步骤和动作，出怪、预部署单位生效或撤回（波次-2 至 波次-6）；
5. Buff：每个单位按创建顺序，它的 Buff 按获取顺序推进时间、触发、到期（状态-3、状态-4）；然后每个单位的生命回复（属性-6）；
6. 敌人的回合，按创建顺序：解除或检查阻挡（阻挡-1、阻挡-3），攻击（敌人攻击-1），没被阻挡、没有攻击的移动，到达目标点（目标-1），移动后再检查阻挡；然后站在地穴上的地面敌人坠落（地图-4）；
7. 光环与在场天赋、范围天赋（职业-13、部署-5、部署-6）；然后座位符文给攻击范围内的干员的技力（符文-5）；然后干员的回合，按创建顺序：先放开阻挡数装不下的敌人（阻挡-3），更新阻挡时免疫与模组的条件增益（职业-10、职业-18），再攻击（攻击-1）；
8. 投射物飞行，命中的结算（攻击-3）；然后直击弹道飞行（敌能-4）、到期的延时爆炸（敌能-3）、【免费品尝】区（敌能-62）；然后发出帧末事件（钩子-3）；
9. 移除生命归零的单位：阵亡的干员解除阻挡，可以再部署；被击倒的敌人触发它的能力（敌能-2）；
10. 判定战斗是否结束（结束-1）。

第 F 帧的指令在执行第 F 帧时生效，执行完帧号加一。

- 来源：推断 INF-0010

### 随机-1 随机数

对局的随机数用 mulberry32，32 位状态存在世界状态里，随快照保存。初始状态取种子的低 32 位。只用 `Math.imul`、移位和异或，所有引擎结果相同。

- 来源：设计决定，见 [ADR 0011](../adr/0011-numerics-integer-frames.md)

### 随机-2 权重随机

从几项里按权重选一项：从对局随机数（随机-1）抽一个 [0, 1) 的数乘以权重总和得到 X，再按顺序从 X 里减去各项的权重，第一次减到不大于 0 时选这一项。只有一项时直接选它，不抽随机数。

- 来源：[PRTS「随机数」oldid=422383](https://prts.wiki/index.php?title=%E9%9A%8F%E6%9C%BA%E6%95%B0&oldid=422383)：「进行权重随机时，会先求和所有事件配置的权重得到总权重，随后生成一个大于等于0、小于总权重的随机数X，随后会从事件列表中依次让X减去该事件的权重值，直至X首次小于/等于0时，选用该事件作为本次权重随机的结果」「如果权重随机的项数只有一个……那不论其权重如何（哪怕其是0权重）也会直接采用该事件，且此时不再属于一次取随机数的行为」

### 同步-1 状态哈希

状态哈希是 32 位 FNV-1a，处理一串数字，每个数字取 IEEE-754 小端字节。这串数字由下面这个对象逐项展开得到：帧号、随机状态、下一个单位编号、下一个出怪序号、全部玩家、全部单位（含基础属性和 Buff）。

展开规则：每个值先记一个类型标记，再记内容。

- 数：−0 记作 0，因为快照（JSON）不能表示 −0；所有 NaN 按同一个值处理。
- 字符串：长度和 UTF-16 码元。
- 布尔值：0 或 1。
- null：只有标记。
- 数组：长度，然后各项。
- 对象：键的个数，然后按键的顺序记每个键（字符串）和值。值为 undefined 的键跳过，因为快照会丢掉它们。

- 来源：设计决定，见 [ADR 0031](../adr/0031-desync-recovery.md)

### 同步-2 快照

快照是世界状态的完整深拷贝，装在第 1 版快照外壳里（ADR 0053），不含当帧的表现事件。从任意一帧的快照恢复后继续执行，每一帧的状态哈希都与不中断执行时相同。外壳格式不对，或数据的帧号与外壳不一致时，拒绝恢复。

- 来源：设计决定，见 [ADR 0053](../adr/0053-interface-schemas.md)
